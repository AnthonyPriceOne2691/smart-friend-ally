# Decisions

- 2026-10-23 · выбрал разрез остатка `memory-extract` на три — `memory-extract` (M26–M28), `memory-sense` (M30, M31), `memory-quality` (M32) — вместо одной поставки, потому что по стенду справки вышло ≈ 930 строк плана при пределе 800; решение ведущего 2026-10-23, подписанное то же, уроки L114–L116 / L117–L118 / L119–L120
- 2026-10-23 · выбрал поправку ×1,3 вместо ×1,8, потому что по L95 правила и ресурсы `memory-guard` уложились в план (258 из 280), а схемы SQL здесь нет; ведущий 2026-10-23: «доводы L95 годятся», стоп 780 прежний
- 2026-10-23 · выбрал номер хода у каждого значения («N: …») вместо номера только у подробностей, как в справке B2, потому что одна опора на все значения короче трёх поисков строки (по имени, по числу, по тексту); цена — форма ответа отходит от замеренной, её качество меряет M32
- 2026-10-23 · выбрал FNV-1a 64 хэшем запроса вместо SHA-256, потому что SHA-256 на Linux требует внешнего пакета, а FNV-1a — форма хэша данных проекта (`Contract.swift`, `BlackBoxRecord`)
- 2026-10-23 · выбрал отбрасывать возраст вне 1–20 до записи вместо записи как есть, потому что CHECK базы (`memory-core`) уронил бы всю сессию одним возрастом мамы; примера нет, случай держит прогон E4B в M32
