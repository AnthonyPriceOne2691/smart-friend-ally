## Problem

- Разбор (`memory-extract`, `memory-sense`) проверен двойником модели; что делает с ним настоящая E4B — не мерили.
  Справка мерила свой Python-стенд (B2: точность 0,84–0,93, полнота 0,85), а не код приложения.

## In scope

1. **Прогон кода приложения на E4B** (Mac, вне git): `MemoryStore.remember` пакета `AllyMemory` этой ветки, модель —
   `llama-server` b10809 (5266f24da) на 127.0.0.1 с теми же весами, что на телефоне (Gemma 4 E4B Q4_K_M, sha256
   `85a896…`), `-c 8192 -np 1 -fa auto --reasoning off --jinja`, грамматика `json_object`, температура 0,2 из
   `extract.json`, seed прогона 42, 7, 1234; `nice -n 10`.
2. **Счёт** (вне git): факты сессии → атомы справки → эталон, ловушки и запретное сессии; паросочетание — сначала
   ловушки, затем обязательное, затем допустимое; повтор известного имени — нейтрален.
3. **Порядок:** доработка — только на сессиях справки s01–s10; свежий набор f01–f10 — один итоговый прогон на коде,
   закреплённом коммитом, счётчик сверяет хэш набора с `frozen.sha256` и печатает по нему только итоговые числа, один
   раз.
4. **Правки кода по прогону справки** — в этой ветке, с тестом на метке M32; **знание:** `engineering/memory` — качество
   на E4B; лог.

## Out of scope

- Телефон, разбор после прощания, цена разбора на телефоне — `memory-app` (M33–M35).
- Новый свежий набор и доработка под свежий набор — запрещены порядком (L49).

## Non-functional

- В git — только документы, числа M32 и знание; правки кода — с тестом и в пределах предохранителя (≈ 100 строк плана,
  стоп 780).
- Mac общий: модель и прогоны — `nice -n 10`, по одному; `llama-server` слушает только 127.0.0.1.

## Risks

- **Свежий набор одноразовый:** провал порога на нём не правится под него — числа идут в отчёт, решение — за родителем
  через ведущего.
- **Секунды на Mac шумные** (общий GPU) — цена разбора меряется токенами, секунды — справочно.
