## Approach

1. **`MemoryBlock.system(persona:block:)`** (AllyMemory): пустой блок — персона как есть; иначе персона, пустая строка,
   блок.
2. **`LlamaModel`:** `tokenCount(_:)` — счёт токенов текста; `rebuildPrefix(_ system:, cache:)` — на очереди модели:
   последовательность 0 из файла состояния по ключу текста или заново, старые файлы префикса удаляются, разговор
   начинается заново.
3. **`MemoryConsole`** (AllyMemory, слова — `memory.json`): строка состояния по базе (факты, эпоха стирания, ожидание,
   отметка неудачи), подтверждение стирания с числом фактов, формы «факт / факта / фактов»; `drain` ставит отметку
   «разбор не удался» в `meta`.
4. **Приложение:** при прогреве — персона + блок (`MemoryBlock` со счётчиком модели); после разбора — пересборка
   префикса, если блок изменился; консоль — строка памяти, «Что помнит Элли» (текст блока), «Стереть память» с
   подтверждением → `eraseAll`, пересборка из персоны.
5. **M40:** подсказки стенда с системным ходом «персона + блок» (блок памяти после справки s01–s10), прогоны `probe-mac`
   обоих вариантов с теми же seed, замороженные проверки стенда, проверки «вываливаний» и имени, слепые судьи пар живости.
6. **Знание:** `engineering/memory`, `engineering/voice-loop`, `ops/test-session`, лог.

## Rejected alternatives

- **Блок ходом пользователя перед разговором** — отклонено: префикс — один системный ход в файле состояния; пустая
  память обязана давать прежний префикс байт в байт.
- **Пересборка только при запуске** — отклонено: в том же запуске следующая сессия не помнила бы разобранное.
- **Строгое «не меньше» в M40** — отклонено: разброс seed в один ответ — шум, как у условия B1 персоны v2.4.
