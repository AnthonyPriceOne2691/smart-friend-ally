# Plan: развернуть канон-контур в Smart Friend Ally

## Approach

Строго по `AGENT_STACK.md` §2.A: ① Delivery → ② CQG (11 шагов §5) → ③ OKF (§0→§5)
→ ④ гейт мержа и CI → снимок канонов (вариант C) → приёмка §6. Payload извлекается
поставляемым `extract_payload.py`, полнота сверяется `--manifest`.

## Stack / boundaries

- Технологический стек продукта — Swift (iOS-приложение), кода пока нет.
- Механика контура — Python и bash; в CI идёт на ubuntu.
- Python- и TS-гейты (ruff, mypy, AST-правила, eslint, dependency-cruiser, Stryker,
  pip-audit, mutmut) — `n/a` с причиной «в проекте нет python/ts-кода продукта».
- Swift: маски длины и grep-правил на `*.swift`, роль «warnings линтера не растут» —
  SwiftLint, гейт «данные ребёнка не попадают в git» — свой, с канарейкой.

## Rejected alternatives

- Развернуть контур позже, с первым кодом — отклонён, потому что пользователь
  решил развернуть сейчас (2026-10-02), а процессная половина (поставки, решения,
  канон домена) нужна уже спайку.
- Создать заготовку Swift-пакета, чтобы гейтам было на что смотреть — отклонён,
  потому что код продукта до спеки нарушает §2.2, а гейты, смотрящие на заглушку,
  дали бы зелёное без смысла. Гейты оживают с первой продуктовой поставкой, и
  приёмка повторяется там.
- Вариант D (тексты канонов локально) — отклонён, потому что репозиторий свой, а
  дефолт для своего — C.
- CI только локально — отклонён, потому что пользователь выбрал приватный GitHub
  (2026-10-02), а локальные хуки обходятся `commit -n`.

## Risks

- Swift-адаптация не проверена на настоящем коде: доктор покажет WEAK/SKIP, и это
  остаток в STACK-ACCEPTANCE, а не успех.
- Путь проекта с пробелом: скрипты контура проверены на «Fake office», риск низкий.
- Активный developer dir — Command Line Tools; Xcode выбирается через `DEVELOPER_DIR`.

## Rollout / migration

Bootstrap мержится через `merge_guard.sh` в main, пока он активная поставка
(§7.2 шаг 6), затем архивируется.

## Test / eval strategy

- `eval-smoke.md` — A1–A7 спеки.
- `delivery/evals/smoke/README.md` — постоянные проверки контура.
