# Decisions

## Серия голоса V1–V4

- 2026-10-23 · выбрал серию из четырёх поставок под одной подписью вместо одной поставки, потому что вся работа ≈ 2 300
  строк при пределе 800 и плане не больше 700 (правило переноса ведущего, L52). Одна подпись — как у D1 и D2.2: родитель
  видит путь целиком.
- 2026-10-23 · выбрал официальный pod Microsoft `onnxruntime-c` 1.28.0 для `AllyOnnx` вместо
  `onnxruntime-swift-package-manager` 1.24.2 и сборки `csukuangfj` 1.28.2, потому что у 1.24.2 API 24 меньше 28 (sherpa
  1.13.8 получил бы null), а сборка csukuangfj — чужая, без своего файла лицензии. sherpa-onnx 1.13.8 ссылается только на
  `_OrtGetApiBase` и `_OrtSessionOptionsAppendExecutionProvider_CoreML` (`nm -u`); оба есть в официальном 1.28.0,
  `ORT_API_VERSION` у обоих — 28. Принято ведущим 23.10; csukuangfj — запасная строка.
- 2026-10-23 · выбрал Swift-слой над C API вместо ObjC-обёртки Microsoft, потому что обёртка той же версии в SPM есть
  только для 1.24.2, а C API у ORT стабилен, и слух может звать его тем же слоем.
- 2026-10-23 · выбрал не класть двоичный sherpa-onnx в V1 вместо общего пакета «на вырост», потому что у него не было бы
  вызывающего, а это мёртвая часть (L50). Его добавит поставка слуха вместе с проверкой пары версий — поправка ведущего
  23.10.
- 2026-10-23 · выбрал один рисковый путь V1 — `Packages/AllyOnnx/` — вместо двух с `Packages/AllyVoice/`, потому что
  нативный рантайм — это потоки, spin, отображение весов и память, а движок — логика над ним; приложение V1 не трогает.
- 2026-10-23 · выбрал синтез по одной фразе со скоростью синтеза не ниже 0,85 вместо всей реплики одним вызовом, потому
  что целые фразы одним вызовом повторяют слова уже с 0,95. По одной фразе при 0,85–1,05 — 0 повторов из 96 на каждой
  скорости, при 0,8 — 3 из 96 (`local/spike/voice-samples/results/repeat_test.json`).
- 2026-10-23 · выбрал не резать фразу по запятым вместо нарезки ради первого звука, потому что кусок кончается падением
  тона, как конец предложения (−4,9 полутона против −5,3), следующий начинается выше (+5,1), а UTMOS ниже на 0,1–0,4.
  Рычаг на первый звук — шаги первой фразы; решает замер на телефоне (вопрос 4 спеки).
- 2026-10-23 · выбрал знак ударения на каждом слове от двух слогов, кроме «ё», вместо знака только на трудных словах,
  потому что без знака голос ошибался в 7 из 14 слов с ударной «е» списка, в том числе «девять» и «десять». Сдвиг «е» к
  «э» со знаками слабый (медиана 11% пути) и проверяется слухом (Z26).
- 2026-10-23 · выбрал пресет по умолчанию «F2+F5:0.5», +1,9 полутона, скорость 0,95, 8 шагов вместо ровно +2 полутонов,
  потому что 1,9 держит скорость синтеза 0,95 / 1,116 = 0,851 не ниже 0,85, а разница в высоте — 10 центов. Это образец
  «F2+F5 помоложе» (UTMOS 4,04); выбор родителя после второго круга меняет эту строку.
- 2026-10-23 · выбрал стадию сдвига `varispeed` по умолчанию вместо `timePitch`, потому что передискретизация чистая
  (UTMOS −0,1 на +2 полутона), а растяжение звука через AVAudioUnitTimePitch дало UTMOS 2,3 — уровень Milena. Сдвиг высоты
  через него не мерен; это вариант конфига, решает второй круг.
- 2026-10-23 · выбрал эталоны звука в `~/models` вместо git, потому что это мегабайты сгенерированного звука. Тест без них
  пропускает с названием причины (П34, L47); крошечная модель `add.onnx` (≈ 150 байт) лежит в ресурсах теста.
- 2026-10-23 · выбрал букву Z для примеров серии вместо продолжения прежних букв, потому что id примеров — общее
  пространство тестов (L51), а поиск `\bZ[0-9]+\b` по тестам main и рабочих деревьев пуст.
- 2026-10-23 · ведущий выбрал вариант (а) — план V1 ≈ 720 строк со стоп-линией 780 — вместо переноса Z6 в V4 и
  сокращения Z3, потому что Z1–Z7 подписаны родителем в этом виде, а резать их значит менять подписанное.
- 2026-10-23 · ведущий разрезал V1 на две поставки по готовым коммитам — V1a `voice-onnx` (AllyOnnx и страж, 300
  строк) и V1b `voice-engine` (движок, 603) — вместо исключения предохранителя, потому что факт 903 > 800 при плане
  720, а разрез не меняет подписанного и отдаёт `AllyOnnx` слуху первым (вариант A `escalation.md` ветки V1).
- 2026-10-23 · выбрал в стороже пропускать `binaryTarget` sherpa из releases с условием платформы вместо запрета
  всего с именем sherpa-onnx, потому что статический xcframework sherpa не несёт ORT (`nm -u`: два символа), а так
  устроен Package.swift k2-fsa 1.13.8, с которого слух берёт подключение — стык исполнителя слуха.
- 2026-10-23 · выбрал имя `VoicePreset` вместо `VoiceSpec`, потому что `VoiceSpec` объявлен в SpeechSynthesis
  macOS (ApplicationServices), и тест на Mac не компилировался из-за неоднозначности типа.
