## Approach

1. AllyCore: `StepThree` — `normalize`, ошибки по словам (Левенштейн), `Pair` (эталон, диктовка, GigaAM) → `Summary`
   (N, WER, разница, интервал парного бутстрэпа на 2000 повторов с фиксированным зерном, точные однословные, пустые,
   вердикт) → строки вывода из `step3.json` (числа 0–100 словами, шаблоны строк). Тесты на Linux.
2. AllyHearing: `StepThreeRun` — обход выгрузки (`*.allybox` → `heard`, `versions.asr`, `child_audio.file`), `refs.csv`
   (`session,turn,ref`, запятая в эталоне — после второй), расшифровка WAV `GigaAMRecognizer`, веса — `asr.choose`
   реестра слуха; пропуски считаются по причинам (нет эталона, нет звука, живой GigaAM); хэши — FNV-1a файлов GigaAM и
   версии iOS записей. Исполняемый `asr-step3` — тонкая обёртка: аргументы → строки → stdout (`FileHandle`), отказ —
   код 1. Тест на Mac — синтетическая выгрузка во временном каталоге из клипов Common Voice с выдуманным `heard`.
3. Знание: `turn-detector.md`, команда в runbook, `knowledge/log.md`.

## Rejected alternatives

- Скрипт Python `scripts/asr_step3.py` (план серии, 130 строк) с распознавателем из пакета pip `sherpa-onnx` —
  отклонено, потому что пакет везёт свой ONNX Runtime другой сборки (новая зависимость и второй рантайм рядом с
  `AllyOnnx`), паритет с телефоном не доказан, а математика правила осталась бы без покрытия Linux; Swift берёт тот же
  `GigaAMRecognizer`, что на телефоне, с паритетом U23 (300 из 300, 88 из 88).
- Таблица по клипам и файл результатов — отклонено, потому что исполнитель не видит её слов (поручение ведущего,
  решение серии), а вердикт по правилу читается из сумм.
