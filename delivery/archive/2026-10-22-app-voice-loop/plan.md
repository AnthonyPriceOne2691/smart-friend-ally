# Plan: голосовой цикл приложения (D1.2 `app-voice-loop`, предпосылка D1.1 `voice-core`)

Уроки архива: **L15** — потолок памяти задаёт подпись; бюджет читается на старте (`os_proc_available_memory`), первый
запуск новой подписи может потребовать доверия сертификату — шаг владельца в плане. **L22** — рядом с числом памяти
пишется метрика платформы: в журнале хода `phys_footprint`, не RSS. **L23** — поддержка русского — проба на
устройстве: консоль спрашивает `DictationTranscriber` на старте, а не верит списку вендора. **L25** — персона v2.4
идёт дословно: правка промпта маленькой модели — новая модель; принятие переносит паритет A23, а не взгляд. **L27** —
порт с паритетом по реальному корпусу находит дефекты: `LlamaModel` против ответов стенда, расхождение разбирается по
токенам, а не подгоняется. **L26, L28** — ноль у прибора на новом стеке и проверка по списку видят только виденное:
`no_network`, `blocking_wait`, `unbounded_stream` и оракул артефакта принимаются пробой с заведомым нарушением
(A7, A8, A13). **L1, L12** — роли `cpu-in-async` и `unbounded-list` ждут `App/*.swift`: первый файл приложения и их
решение — один коммит, иначе мета-гейт красный. **L32** — статусы ролей пишутся словами, которые читает разборщик
карты ролей (`delivery/STACK-ACCEPTANCE.md`). **L31** — после правки конфигов гейтов доктор: DEAD 0, число
просмотренных файлов растёт. **L2** — новый манифест — одна строка `new_dependency` на путь. **L3, L5** — шаблон CI
несёт допущения чужого стека: macOS-джоба проверяется прогоном, а не чтением. **L10** — условие шага — код возврата
гейта, а не вывод `grep` (шаг сверки дайджеста D1.1, macOS-джоба). **L6** — канон не правим: адаптация — конфигами,
находки наверх — инцидентами. **L14** — после наката канона или ребейза на ветку маршрутизатора — сразу строгий
`delivery_check --require-ci --diff-base origin/main`. **L17, L19** — пороги A9–A10 записаны до прогонов на телефоне и
не двигаются после. **L7, L16** — границу данных («веса и журнал вне бэкапа, слов нет») ищем по всем концептам поиском,
а не по памяти. **L36** — лицензия зависимости — из открытого источника: llama.cpp — MIT по `gh api`, ассет b10809 по
API — тот же sha256. **L37** — слова сопровождающего и архитектора — гипотеза до пробы: символы iOS-среза, слепота гейта
к `.binaryTarget` и правило нарезки A3 перепроверены прогоном — правило A3 неверно, слепота гейта неполна (новый
манифест он видит целиком), символы подтвердились. **L33** — спека, план и примеры — первым коммитом ветки, до кода.

## Approach

1. **Порядок.** Подпись родителя под спекой, планом и списком имён → ветка `feat/voice-core` с документами D1.1
   (спека — раздел «Предпосылка» таблицей, подпись — ссылкой на коммит этой спеки) → D1.1 через `merge_guard` →
   ребейз этой ветки → `eval-smoke.md` → implement D1.2 срезами. Код D1.2 не трогает `AllyDiscipline` (там серия
   маршрутизатора) и `AllyCore` (кроме вызова).
2. **Модель (`Packages/AllyLlama`).** Порт `LlamaEngine` (`local/spike/phone/app/Sources/Shared/LlamaEngine.swift`):
   загрузка с mmap и ленивым чтением, ход `<|turn>user … <|turn>model` поверх KV, цепочка top-k → top-p → min-p →
   температура → dist(seed), неполный UTF-8 хвост не отдаётся. Новое — по замерам стенда `local/spike/llm-runtime/`
   (`results/summary.md`, 2026-10-19): n_ctx 8192, `n_seq_max` 4 с общим KV и `swa_full` = true — системный ход персоны
   (1764 токена) живёт мастер-последовательностью, разговор — её копией (`llama_memory_seq_cp`), новый разговор —
   `seq_rm` и снова копия; без полного окна копия мастера падает (`llama_decode` = 1, «no slot»), а срез хвоста для
   перебивания (D3) за ~236 токенов молча портит KV. Цена — KV 448 МиБ при 8192 вместо 168 из черновика
   (`local/research/memory/report.md:190` считал без полного окна); 4 последовательности оставляют место второму
   мнению маршрутизатора в том же батче. Мастер пишется файлом состояния (48,7 МБ, запись 0,02–0,05 с, чтение
   0,02–0,11 с на Mac) с ключом из хэшей персоны и весов, сборки llama.cpp и параметров контекста; холодный промпт
   (≈ 4,6 с до первой фразы на телефоне) в ходе не бывает никогда. Разговор держится в KV: с ним время хода не растёт,
   повторный prefill истории к 8–10-му ходу стоит +1,4 с. Ещё: актор на своей последовательной очереди (блокирующий
   `llama_decode` не занимает кооперативный пул), `AsyncThrowingStream(bufferingPolicy: .bufferingNewest(1))`
   накопленного текста, отмена флагом на каждом токене плюс `llama_set_abort_callback`. Параметры — из реестра.
3. **Приложение (`App/`).** Три каталога рисковых путей и только они трогают политику платформы: `Audio/` — сессия,
   разрешение микрофона, тап, голос; `Speech/` — `DictationTranscriber`; модель — пакет. `VoiceLoop.swift` собирает
   ход: тап → кадры в определитель D1.1 и распознаватель → конец речи (хвост 0,8 с) → микрофон закрыт →
   `finish` распознавателя → `TurnRunner(mode: .talk)` → строка журнала. Загрузка: реестр → проверка весов (D1.1) →
   модель → мастер-префикс из файла состояния или сборкой с записью файла → прогрев «Привет!» без звука (первая сборка
   шейдеров Metal ≈ 13 с один раз после установки — этапом в консоли) → распознаватель → голос по идентификатору →
   строки готовности и срок подписи (разбор D1.1 над `embedded.mobileprovision`). Консоль — один экран SwiftUI, тап по
   кнопке с `accessibilityIdentifier`, до готовности недоступен.
4. **Реестр `model.json`:** `model` (файл, байты), `runtime` (сборка b10809, n_ctx 8192, n_batch 2048, n_ubatch 512,
   потоки 4, слои 99, ленивое чтение, flash auto, `n_seq_max` 4, общий KV, `swa_full`), `sampling` (0,7 / 0,95 / 40 /
   0,05, 256, seed 42), `persona` (файл),
   `voice` (идентификатор Milena), `vad` (хвост 800 мс), тайм-ауты (слушать 8 с, первая фраза 10 с). Хэшей в нём нет:
   пины — в снимке `delivery/model_surface.txt` (`<путь-или-ключ>\t<sha256>`, после `git add`), checksum
   `binaryTarget` — в `Package.swift` с `pragma: allowlist secret`.
5. **Веса на телефон** — командой концепта: sha256 на Mac (`85a896…`) → `devicectl device copy to` в
   `Library/Application Support/Models/` (4,64 ГБ, ≈ 213 с у зонда); приложение ставит `isExcludedFromBackup` на
   каталог и читает его обратно.
6. **Гейты.** `.swiftlint.yml`: `included: App`, три правила (`no_network`, `blocking_wait`, `unbounded_stream`);
   `not-applicable.json` — две роли из «до кода» в правила; канарейки ролей; jscpd и счётчик ратчета SwiftLint видят
   `App` и `AllyLlama` (env и свой скрипт, канонные не правятся); `check_app_artifact.sh` — свой гейт с канарейкой;
   `.github/workflows/ios.yml` — `workflow_dispatch`, macOS, `timeout-minutes` 30; запись в `adapted.json`.
7. **Доказательства.** Mac: A23, A7–A8 на подписанной сборке. Телефон: A9–A12, A20–A21, A24 —
   `devicectl device process launch --console`, журнал `devicectl device copy from`, снимки экрана в `local/`.
   В verify-report: «Исполнение рисковых путей» (три пути, команды, at=), «Изменение поверхности модели» (персона,
   реестр, пакет — хэши, A23, рантайм b10809 на входе и выходе прогона), дайджест утверждений, ссылка на CI.
8. **Знание и наверх.** Концепт `engineering/voice-loop.md` (Runbook: сборка, веса, запуск, журнал) с
   `implementation:`; ADR `engineering/app-architecture.md` с отказами ниже (класс L); карта репозитория; реестр правил
   в `safety-below-model.md`. Инциденты: `.binaryTarget` в существующем манифесте гейт `new-dependency` не видит;
   `BUILD_MARKERS` не знает XcodeGen/Xcode — правило §6.5a у iOS-проекта молчит даже на handoff.

## Stack / boundaries

- Swift tools 5.10 (как `AllyDiscipline`); `AllyCore` — Foundation, Linux CI; `AllyLlama` — Apple, тесты на Mac и в
  ручной macOS-джобе, в Linux-джобу не входит; `App` — iOS 26 (`DictationTranscriber`), XcodeGen 2.46.0, Xcode 27 через
  `DEVELOPER_DIR`. Сетевых API нет ни в одном слое.

## Rejected alternatives

- **Один D1 на ≈ 1 300 строк с подписанным предохранителем** — отклонено, потому что родитель в E1 оставил 800 строк и
  25 файлов, а ревью 1 300 строк одним PR и разбор составного отказа на телефоне дороже второго PR.
- **Ядро — в D2, как велит «переноси в D2»** — отклонено, потому что без `TurnRunner` цикл D1.2 не может звучать через
  контракт, а это цель D1; у ядра нет рисковых путей, и E1 ему не нужно.
- **Нарезка первой фразы `Contract.sentence` по сырому тексту (черновик, A3)** — отклонено, потому что контракт чинит
  ответ до нарезки: на «Слон весит 2.5 тонны. Это очень много!» сырая граница отдаёт «Слон весит 2.», и звучит «Слон
  весит два. Это очень много!» — проверено прогоном контракта 2026-10-19.
- **LiteRT-LM вместо llama.cpp** — отклонено, потому что GPU-делегат закрыт, Swift API — превью, есть баг с цифрами на
  fp16, а llama.cpp держит E4B в 0,4–0,5 ГБ с p95 1,9 с (`model-on-phone.md`).
- **SpeechTranscriber или `SFSpeechRecognizer`** — отклонено, потому что у первого нет ru-RU на iOS 27.0.1 (L23), а
  второй может распознавать на сервере.
- **Голос «максимального качества» и веса в `Documents`, как у зонда** — отклонено, потому что мягкий выбор молча
  подменяет голос (П23), а `Documents` уезжает в бэкап iCloud.
- **`.xcodeproj` в git** — отклонено, потому что pbxproj — сгенерированный файл, съел бы предохранитель и конфликтовал
  бы при каждом ребейзе; источник — `App/project.yml`.
- **Хэши весов и персоны в `model.json`** — отклонено, потому что detect-secrets принимает 64-значный hex в кавычках за
  секрет (замер 2026-10-19: Hex High Entropy на обоих), а запись в `.secrets.baseline` — лишние строки в предохранителе.
- **macOS-раннер на каждый PR** — отклонено (E3), потому что минуты macOS ×10 (CQG §8.7), а ядро и форму кода уже судит
  Linux-джоба.
- **Малое окно SWA (`swa_full` = false, KV 168 МиБ, как в черновике)** — отклонено, потому что копия мастер-префикса с
  ним падает (`llama_decode` = 1, «no slot»), а срез хвоста ответа (перебивание, D3) на хвосте 600 токенов молча
  расходится с контролем (max|Δ| логитов 0,36 при «успешном» `seq_rm`; стенд 2026-10-19); полное окно стоит +280 МиБ.
- **Сборка префикса персоны на каждом запуске, как у зонда** — отклонено, потому что это ≈ 3,8 с prefill на запуск против
  0,02–0,11 с чтения файла состояния 48,7 МБ; холодный промпт в ходе (≈ 4,6 с до первой фразы) вне гейта времени.

## Risks

- Запас предохранителя D1.2 — ≈ 45 строк; порог стопа назван выше.
- Память: KV 448 МиБ при полном окне SWA — порог A9 поднят до 1000 МБ до прогона (L19), ожидание ≈ 0,75 ГБ; на
  Mac сверить размеры буферов в журнале llama.cpp с реестром до установки на телефон.
- Ресурсы `AllyDiscipline` грузятся через `Bundle.module` с `fatalError`: бандл ресурсов пакета в приложении проверяет
  первый же запуск (A9) — до тапа.
- Бесплатная подпись: лимит приложений на телефоне (зонды держат ~8 ГБ весов в контейнерах) и доверие сертификату —
  шаги владельца; подпись живёт 7 дней — счётчик A21, переустановка одной командой — D2.
- Паритет A23 ниже 35 из 37 или токены промпта не 37 из 37 — порт расходится со стендом (L27): разбор по токенам и
  правка порта, не порога; допуск в 2 кейса — замеренный разброс между режимами кэша (58 из 60), а не запас на ошибку.
- На раннере GitHub может не оказаться Xcode с SDK iOS 26+: тогда сборка `.app` — локальным свидетельством, запись в
  STATUS (E3).
- Нагрев к 20-му ходу (зонд: 17,1 → 11,9 ток/с за 31 реплику, телефон до `fair`) при петле ≈ 2,0–2,2 с с персоной
  v2.4 — порог A10 взят по цели проекта, не по свежему разговору; KV разговора держится, повторного prefill истории нет.
- Параллельная серия маршрутизатора и накаты канона — ребейз перед `merge_guard`, строгий `delivery_check` (L14).

## Rollout

`manual-deploy`: сборка на Mac, `devicectl device install app`, веса — командой концепта; телефон не блокировать
во время прогонов (блокировка останавливает GPU, `ProbeApp.swift:43`). Шаги владельца: доверие сертификату, если
iOS спросит (L15); удаление зондов, если не хватит места или лимита бесплатной подписи; 20 фраз на динамике и 5 в
авиарежиме.

## Test / eval strategy

- `eval-smoke.md` — до implement, после подписи: строки A7–A13, A20–A24 с командой и ожиданием; факт — по прогону.
- Ядро — тесты D1.1 с метками `// A<n>`; паритет — `swift test --package-path Packages/AllyLlama --filter A23`.
- Детектор реляционных оракулов знает только hypothesis и fast-check: Swift-свойства (A3, A17) он не видит —
  предупреждение разбирается в verify-report, как в closing-question.
