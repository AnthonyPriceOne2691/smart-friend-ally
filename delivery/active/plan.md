## Подход

1. **Сессия (AllyCore):** у отмены хода появляется причина — стоп родителя, перебивание, прерывание аудиосессии. Путь
   отмены один (`perform`), различается только то, что после неё:
   - стоп родителя — запись `cancelled` с концом `parent`, сон (как сейчас);
   - перебивание (`SessionEvent.bargeIn`) — запись `cancelled` с этапом `barge_in: 1`, без конца, сразу слушание;
   - начало прерывания (`interruptionBegan`) — запись `cancelled` с этапом `interrupted: 1`, состояние `paused`, поза
     «спит»;
   - конец прерывания (`interruptionEnded`) — слушание.
   Во всех трёх случаях `commit` доигранного делает раннер на отмене (D5, X2) — новой памяти не нужно. Перебивание
   принимается, только пока Элли говорит; в другом состоянии событие ничего не меняет (автомат сессии, L59).
2. **Драйвер (`Conversation`):**
   - `bargeIn()` — тап по Элли во время речи и кнопка консоли «Перебить»;
   - цикл слушания переживает паузу: ждёт конца прерывания, а не выходит;
   - перебивание от слуха (первое наложение D6.1) идёт в сессию тем же событием.
3. **Счётчик D6.1 в режиме действия:** первое наложение за голос — одно событие перебивания; кашель и «ой» короче
   250 мс — ничего (X15).
4. **Приложение:**
   - `AudioIO` — уведомления о прерывании аудиосессии (начало, конец) → события сессии; после конца движок запускается
     снова; наложение → `bargeIn`;
   - детский экран — тап по Элли, пока она говорит, → `bargeIn()`; консоль — кнопка «Перебить».
5. **Знания:** `engineering/session` (причина отмены, пауза, перебивание), `engineering/voice-loop` (перебивание,
   прерывания), `product/look-and-feel` (правило 7 исполняется), `knowledge/log.md`. Места «перебивания нет», «D6»
   ищутся по смыслу границы (L70).

## Уроки архива по затронутым путям

- **L58** — новое событие теряется на обёртке: `Conversation` передаёт `bargeIn`, пауза и прерывания проходят через
  драйвер, тесты идут через драйвер, а не только через `Session`.
- **L59, L60** — порядок «отмена → стоп голоса → отмена модели → `commit`» держит одна отмена хода и очередь модели,
  а не сверка; позднее перебивание после конца голоса автомат сессии не берёт.
- **L69, L71** — две сессии на одном слухе: перебивание идёт той, что говорит; прерывание аудиосессии касается общего
  движка — обеих.
- **L111** — гонка «ход кончился — перебивание пришло» в тестах судится по состоянию, а не по паузе виртуального
  времени.
- **L112** — у отмены меняется смысл (сон → сон, слушание или пауза): все вызывающие `cancel` и `stop` ищутся по
  предположению «отмена хода = сон», а не по имени.
- **L72, L41** — ожидания в тестах — через `eventually` с пределом настоящего времени.
- **L50** — у события перебивания есть вызывающие в этой же поставке: слух и экран.
- **L79, L113** — метки X13–X17 — первым токеном комментария на строке теста.
- **L33, L51** — документы первым коммитом; X13–X17 перенесены из спеки серии без изменения смысла.
- **L34, L52, L61** — поправка бюджета +50% (слово ведущего); стоп-линия 780.
- **L56, L57, L46** — не применимы: звук и данные ребёнка D6.2 не пишет, экран телефона не снимается.

## Rejected alternatives

- **Перебивание только тапом** — отклонено, потому что пятилетка не тапает, а говорит (решение родителя 3).
- **Отдельный путь отмены для перебивания** — отклонён, потому что одна отмена держит П28 и `commit` доигранного D5; два
  пути разошлись бы, как обёртки L58.
- **Досказать прерванный звонком ответ после паузы** — отклонено, потому что момент прошёл: после звонка она начинает
  заново, а несказанное в памяти модели всё равно не числится (D5).
- **Порог наложения выше на время голоса** — отложено, потому что без записей это догадка; реестр слуха поднимет его без
  кода (D6.1).
