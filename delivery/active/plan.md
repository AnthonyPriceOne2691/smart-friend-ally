# Plan — D5 kv-spoken (серия «живой разговор»)

Спека серии — коммит b7ef7b0; подпись родителя — отдельным коммитом до кода (L33). Код — после мержа D7.1
`turn-speculation`: D5 меняет её счётчик `spec_stale`.

## Подход

1. **Порт модели** (`AllyCore/Ports.swift`): у `LanguageModel` три новых метода.
   - `commit(spoken:)` — ход модели в памяти становится прозвучавшим, её реплика остаётся;
   - `retract()` — последний ход уходит целиком;
   - `remember(heard:spoken:)` — ход без модели (заготовка, запасная фраза) ложится в память.
2. **Что прозвучало** (`TurnRunner`):
   - список предложений, чей `speak` вернулся, пока ход не отменён; оборванное — не в счёт;
   - в конце хода и при отмене раннер зовёт `commit(spoken:)` с этим списком;
   - `TurnOutcome.spoken` отдаёт его сессии и следу.
3. **Сессия** (`Conversation`):
   - заготовка маршрутизатора и фраза отказа → `remember(heard:spoken:)`; реплика с `forget` — ничего;
   - молчаливый ход спекуляции, после которого она продолжила, → `retract()` и поле следа `spec_retracted` вместо
     `spec_stale` D7.1. Строки D7.1 — дословно, со слиянием сложением (L68).
4. **`LlamaModel`** (`AllyLlama`, рисковый путь):
   - начало ответа хода запоминается;
   - стоп больше не стирает её реплику — уходит только сгенерированное;
   - `commit` — `seq_rm(1, начало ответа, −1)`, затем дописывается прозвучавший текст;
   - `retract` — `seq_rm(1, начало хода, −1)`;
   - `remember` — её реплика и прозвучавший текст как полный ход, без выборки токенов;
   - всё — на последовательной очереди модели, после отмены по порядку (L59, L60);
   - `swa_full: false` в `model.json` — ошибка загрузки и строка консоли (X7).
5. **Обёртки и двойники**: каждый `LanguageModel` (двойники AllyCore, адаптер приложения) несёт три метода — новый метод
   теряется на обёртке (L58); поиск по `LanguageModel` во всех пакетах и `App/`.
6. **Знания:** `engineering/on-device-model.md` (память модели — только прозвучавшее, `swa_full` обязателен),
   `engineering/session.md` (вызовы после хода, `spec_retracted`), `safety-below-model.md` (срезанное контрактом в
   память модели не попадает), `knowledge/log.md`. Места «KV диалога», «весь ответ» и «spec_stale» — поиском по смыслу
   границы (L70).

Уроки этой поставки при сдаче — L111–L113 (номера ведущего 2026-10-23; подпись называла L95–L97, L95 раньше занял

## Уроки архива по затронутым путям

- **L58** — новые методы порта теряются на обёртке: поиск всех `LanguageModel`, тест через драйвер, а не только прямой
  вызов.
- **L59, L60** — порядок «отмена → чистка → commit» держит последовательная очередь модели, а не сверка; методы не
  блокируют сессию.
- **L68** — строки `spec_stale` D7.1 переносятся дословно; конфликт — сложением.
- **L70** — места знаний ищутся по смыслу границы, а не словами прошлой поставки.
- **L22** — отпечаток в X8 — footprint, а не RSS.
- **L44, L45** — `swa_full` читается из JSON как Bool явно; числа — как Double.
- **L61, L34, L52** — поправка бюджета — +50% (слово ведущего).
- **L33, L51** — спека отдельным коммитом до кода; id X1–X17 в тестах не встречались до спеки.
- **L40, L41** — первое предложение уходит в голос сразу, `commit` его не задерживает; покрытие — по своему пакету.
- **L50** — у новых методов есть вызывающие в этой же поставке: раннер и сессия.
- **L56, L57** — не применимы: звук и данные ребёнка D5 не трогает.
- **L46** — не применим: экран телефона не снимается.
- **L69** — не применим: очереди к микрофону D5 не трогает (это D6.1).
- **L19, L20, L23, L25, L28, L29, L30, L35, L38, L39, L47, L48, L49, L65, L66, L67** — правила и замеры безопасности
  (контракт, маршрутизатор, промпт, проверки) D5 не меняет. Из них в силе L35 (`mergeable` до ссылки на прогон) и L67
  (паритет — по всему корпусу) — для X1 и X6 сравнение идёт со стендом 19.10 на тех же длинах хвоста.

### После слияния main с D7.1 — уроки по тем же путям (2026-10-23)

- **L7, L16** — граница «в памяти модели — только прозвучавшее» живёт в нескольких местах. Места найдены поиском по
  `KV`, «весь ответ», `spec_stale`, «в памяти модели», а не по памяти: `session`, `voice-loop`, `safety-below-model`,
  `engineering/index`. ADR `on-device-model` память разговора не описывает — его не трогаем.
- **L71** — применим как проверка, а не как правка: обе сессии приложения (консоль и детский экран) делят одну
  `LlamaModel`, поэтому память D5 общая, как и KV раньше. Сессии не идут одновременно (новая будится после конца
  прежней), поэтому вызовы `commit`, `retract` и `remember` разных сессий не перемешиваются. Экранных действий D5 не
  добавляет.
- **L72** — ожидание X4 (сессия видит конец начатого ответа) идёт через `eventually` с пределом 10 с настоящего
  времени: при поломке тест краснеет, а не виснет.
- **L73** — D5 входит через существующие швы (обёртка `Speculation`, выход `TurnRunner`, `respond` сессии). Из прежних
  тестов менялось только утверждение памяти в U8 (память двойника теперь в терминах D5); U12 заменён на X4 по спеке.
- **L89, L90, L91** — не применимы: подписи, пороги и ресурсы приёмки D5 не трогает. Ресурс `lines.json` — 4 строки;
  бюджет — net 325 при плане 280 (+16%).

## Rejected alternatives

- **Снимок состояния и полный prefill сказанного** — отклонён, потому что `seq_rm` при `swa_full` точен (X6, стенд
  19.10), а снимок — 54 МБ на ход.
- **Оставлять в памяти оборванное предложение целиком** — отклонён, потому что модель «сказала» бы то, чего дочь не
  слышала (решение 1 спеки).
- **Дописывать сказанное одним батчем со следующей репликой** — отложено, потому что это оптимизация («собираем сейчас»),
  а prefill 12–64 токенов почти не дороже.
