# Plan: качество разбора памяти на E4B (`memory-quality`)

Уроки архива. **L19, L25**: пороги и правило суда — коммитом до итоговых прогонов; правка промпта — новая поверхность,
её принимает только повторный прогон справки. **L49**: свежий набор — один итоговый прогон, исполнитель его не
открывает, счётчик печатает только итоговые числа и сверяет хэш (`freeze.py --check`). **L28, L115, L117**: словари
окна, отрицания и хозяина видят только виденное — их доводка идёт только на справке. **L116, L95**: правки кода по
прогону — правила, поправка ×1,3; предохранитель 800, стоп 780. **L114, L118**: утверждения о составе — целиком или
множеством. **L75**: метка `// M32` в строке `func test`. **L33**: документы — первым коммитом. **L41**: покрытие —
по своему `Sources/`. **L45**: числа JSON — явными типами. **L50, L70**: у разбора нет вызывающего до `memory-app` —
знание так и пишет. **L26, L43, L35, L14**: дайджест, `mergeable`, строгий `delivery_check` после слияния main. Не
применимы: **L76** — новых файлов хранилища нет; **L29, L30, L47, L48** — судей и сравнения моделей нет, порог один и
записан; **L74** — схемы SQL нет. Уроки сдачи — **L119, L120**.

## Approach

1. **Стенд вне git** (`local/research/memory/quality/`): `runner/` — SwiftPM-исполняемый файл на `AllyMemory` этой
   ветки, `MemoryModel` через `llama-server` на 127.0.0.1; `score.py` — атомы, паросочетание, проверки справки, режим
   свежего набора с однократным счётом и сверкой хэша; `serve.sh` — сервер на 127.0.0.1 через `nice -n 10`.
2. **Отладочный прогон справки** (seed 42) — разбор находок: ловушки, запретное, «Мурка — кошка».
3. **Правки кода по находкам** — в пакете памяти этой ветки, с тестом `// M32`; повтор прогона справки.
4. **Итог:** справка × 3 seed; затем коммит-замок кода и свежий набор × 3 seed, один счёт.
5. **Знание:** `engineering/memory` — качество на E4B с числами; лог.

## Rejected alternatives

- **Прогонщик в репозитории за переменной окружения** — отклонено решением ведущего 2026-10-25: код, который ходит на
  localhost, в репозиторий не идёт.
- **Python-стенд справки вместо кода приложения** — отклонено: M32 меряет разбор приложения, а не прототип.
- **Порог на каждый seed отдельно** — отклонено: при 10 сессиях одна лишняя строка в seed двигает точность на 2–3 п.п.;
  сумма трёх seed — тот же объём, что у справки (37 обязательных × 3).

## Test / eval strategy

- Правки кода — тестом `// M32` с двойником модели на случаях справки (вымышленных); мутации правок.
- Замер — `score.py`: справка — по сессиям и проверкам; свежий набор — только итоговые числа, один раз.
