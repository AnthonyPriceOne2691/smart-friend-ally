## Approach — Э1

1. **Порядок.** Подпись родителя под спекой, планом и ответами 1–8 → `eval-smoke.md` (P1–P12) до кода → эталон
   `local/spike/erudition/reference.py` заморожен хэшем → срезы `tasks.md` → verify → handoff. `AllyDiscipline`,
   `AllyLlama`, `App/` и `Session` не трогаем, `AllySQLite` берём как есть.
2. **Основы слов (`RussianStemmer.swift`).** Перенос алгоритма Snowball для русского со snowballstem.org:
   - гласные «аеиоуыэюя»; RV — после первой гласной, R2 — по определению алгоритма;
   - шаг 1: деепричастие совершенного вида; иначе возвратная частица, затем прилагательное с причастием, иначе глагол,
     иначе существительное. Окончания первой группы — только после «а» или «я». Из списка берётся самое длинное
     совпадение без отката к короче, как `among` у Snowball;
   - шаг 2 — «и»; шаг 3 — словообразовательное «ост(ь)» в R2; шаг 4 — «нн» → «н», превосходная степень, «ь».

   Вход — уже нормализованное слово («ё» → «е»). Списки окончаний — массивы коротких литералов; `inline_prompt` их не
   трогает, у литерала меньше 40 знаков.
3. **Текст и конфиг (`EncyclopediaText.swift`, `Resources/encyclopedia.json`).** `EncyclopediaConfig: Decodable` хранит:
   - стоп-слова, рамки, вопросительные слова (как `QWORDS` справки, включая «пачиму» и «посему»), «моё/твоё»;
   - деликатные начала слов («умер», «умир», «смерт», «погиб», «мертв», «убил», «убив», «убий», «войн», «похорон»,
     «кладбищ»);
   - синонимы (словарь `SYN` справки), веса полей, `k1`, `b`, буст;
   - предел ответа 130 знаков и 2 предложения; «одно может не найтись из трёх и больше».

   Нормализация: `lowercased()`, «ё» → «е», NFD → снять U+0301 и U+0300 → NFC, слова `[а-яa-z0-9]+`. Ключи синонимов
   приводятся к основам один раз при загрузке (L39).
4. **Индекс (`EncyclopediaIndex.swift`) — SQLite FTS5 через `AllySQLite`.**
   - Соединение `:memory:`; таблица `CREATE VIRTUAL TABLE cards USING fts5(title, alias, body, tokenize='unicode61
     remove_diacritics 0', content='', detail=full)`. `rowid` — номер карточки в базе плюс один.
   - Поля карточки: первая формулировка, остальные формулировки, ответ. Токены — основы через пробел без стоп-слов; рамки в
     документе остаются, как у эталона.
   - Запрос: `SELECT rowid, bm25(cards, 4, 2, 1) FROM cards WHERE cards MATCH ? ORDER BY 2 LIMIT 50`. Выражение `MATCH` —
     `"основа" OR "основа"` по разным основам запроса и синонимов, кавычки внутри удваиваются. Счёт — модуль `bm25`.
   - Буст первой формулировки — в Swift: × (1 + β · доля её основ в запросе); сортировка — счёт по убыванию, при равенстве
     — номер карточки.
   - Соединение одно на экземпляр, под `Locked`: сессия зовёт из актора, инструмент — из одного потока.
   - Таблица не создалась или запрос упал → `healthy == false` с правилом `knowledge.index_failed` (П33).

5. **Решение (`Encyclopedia.swift`).** `lookup(_:) -> Lookup { hint: String?, record: KnowledgeRecord }`, по порядку:
   - нет вопросительного слова → `knowledge.not_asked`;
   - «моё/твоё» → `knowledge.personal`;
   - деликатное начало слова → `knowledge.delicate`;
   - нет значимых слов или ни одна карточка не делит основу → `knowledge.no_match`;
   - лучшая карточка не покрывает значимые слова (основа или основа синонима — в её формулировках; при трёх и больше одно
     может не найтись) → `knowledge.coverage`;
   - иначе подсказка — ответ карточки, `knowledge.hint`.

   `KnowledgeRecord { card: String?, rules: [String], dataHash: String }` — без слов.
6. **Самопроверка (`Encyclopedia.init(cards:config:)`).**
   - Проверяется: строки JSONL декодируются; id латиницей через дефис и уникален; 3–6 разных формулировок; ответ — только
     разрешённые знаки, ≤ 2 предложений, ≤ 130 знаков; конфиг с весами полей; первая формулировка каждой карточки находит
     её с подсказкой.
   - Любой сбой → `healthy == false`, на каждый `lookup` — `knowledge.selftest_failed` без подсказки; отказ SQLite —
     `knowledge.index_failed`.
   - Хэш — `FNV1a.tag(конфиг + карточки)`.
7. **Инструмент (`Sources/EncyclopediaReplay/main.swift`, цель `encyclopedia-replay`).**
   - Запуск: `swift run -c release --package-path Packages/AllyCore encyclopedia-replay <база.jsonl> < вопросы.jsonl >
     решения.jsonl`.
   - Строка входа — `{"id","text"}`, выхода — `{"id","hint","card","rules","top"}`, где `top` — тройка «карточка:счёт».
   - В stderr — хэш базы, время загрузки и p50 и p95 поиска, лучший из трёх замеров на строку.
   - Текстов вопросов инструмент не печатает: для слепого набора он безопасен в руках ведущего.
8. **Эталон и паритет (стенд, вне git).**
   - `reference.py` — конвейер справки (`textproc`, `fts_eval`) со строгим правилом и порядком решения Э1, из
     `analysis/rules_cards_only.py` и `analysis/fixture_examples.py`; хэш — в `decisions.md` до прогона.
   - `parity.py` гонит обе реализации на 300 вопросах v1 и v2 и 55 карточках стенда и печатает суммы: совпало решений,
     карточек, троек и счётов с допуском 1e−9; итоги классов. Стенд — `local/research/encyclopedia/.venv`.
9. **Знание.**
   - Концепт `knowledge/engineering/encyclopedia.md` (type Design): движок, формула, правило с таблицей замера, схема
     карточки, самопроверка, запись, «приложение не зовёт до Э3». В `implementation:` — четыре исходника и
     `encyclopedia.json`.
   - Правки мест L16, `engineering/index.md`, карта репозитория (AllyCore, `encyclopedia-replay`), `knowledge/log.md`.
   - Справка `kids-encyclopedia.md` получает строку-ссылку на замер 2026-10-23, текст справки не меняется.

## Stack / boundaries

- Swift tools 5.10, XCTest; джоба `swift` на Linux — AllyCore. На Mac — тулчейн Xcode через `DEVELOPER_DIR`, SwiftPM —
  с `--disable-keychain`.
- **SQLite — общий пакет `Packages/AllySQLite`** (вводит `memory-core`): модуль `CSQLite` и обёртка. AllyCore получает
  зависимость `.package(path: "../AllySQLite")`. Это пакет проекта, а не внешняя зависимость: гейт `new-dependency`
  считает только пакеты с `name:` или `url:`, поэтому `new_dependency: none`. Строка `LINT_SWIFT_PACKAGES` и исключение
  `.build` в SwiftLint приходят с пакетом.
- NaturalLanguage не берётся. Snowball — свой код по описанию алгоритма (BSD-3; строка в концепте для будущего экрана
  лицензий).
- Зависимости вниз: App → AllyLlama → AllyCore → Discipline, AllySQLite. Энциклопедия живёт в AllyCore и `Discipline` не
  зовёт; маршрутизатор в тестах базы зовётся только в Э2.

**Порядок с `AllySQLite`.** Пакет в main к началу реализации Э1 — Э1 подключает его: +3 строки `Package.swift`. Э1 готова
раньше — пакет вводит маленькая поставка `sqlite-core` по API спеки памяти (вопрос ведущему В1). Внутри Э1 он пробил бы
предохранитель: +≈ 130 строк к ≈ 560.

## Rejected alternatives

**Движок и данные:**
- **Свой BM25 на Swift по индексу в памяти** (первая редакция этой спеки) — отклонено решением ведущего 2026-10-23:
  SQLite — один пакет на приложение, FTS5 проверен на macOS и Linux, движок тот же, что у эталона. Формула сверена на
  пробе и остаётся выходом, если FTS5 не окажется на iPhone.
- **Свой модуль SQLite в AllyCore** — отклонено: два модуля с одним именем цели не соберутся в одном графе SwiftPM, а
  память берёт тот же пакет.
- **Леммы NLTagger, как в справке** — отклонено: на Linux их нет, на iPhone не проверены, меняются с обновлением iOS
  (П26), а строгое правило на леммах не лучше (`decisions.md`).
- **Файл базы в `Caches` телефона** — отклонено: таблица на 300 карточек строится в памяти при прогреве [оценка ≈ 10 мс],
  а файл приносит спутники (`-journal`, `-wal`), место и вопрос бэкапа.
- **Готовая база SQLite в бандле, собранная на Mac** — отклонено: файл с сигнатурой SQLite в дереве блокирует коммит
  (`data-magic`), а сборочная фаза XcodeGen — сборка, не оракул.
- **Шумовая модель распознавания, как у маршрутизатора** — отклонено сейчас: она добавляет совпадения, а правило держит
  точность. Вернуться по промахам на шумных вопросах из чёрного ящика.
- **Векторный поиск (e5-small)** — отклонено решением 2026-10-17 и замером справки. Вернуться, если промахи на детских
  вопросах из чёрного ящика больше 10%.
- **Усечение до пяти букв (`retrieve.py` стенда)** — отклонено: hit@1 72% против 86% у Snowball с рамками и бустом
  (справка, v2).
- **Сравнение основ по общему началу в пять букв** — отклонено: на открытых наборах +1 верная и +1 неверная, сложности
  больше, пользы нет (`analysis/rules_prefix.py`).

**Правило:**
- **Правило справки (покрытие ≥ 0,5 по всей карточке)** — отклонено: 58 неверных из 178 без карточки.
- **Покрытие = 1 (все слова без исключения, по формулировкам)** — отклонено: 49 верных из 90 против 72 ради 1 неверной
  без карточки вместо 4.
- **Выбрасывать негодные карточки, а остальные держать** — отклонено: дефект прятался бы в урезанной базе;
  маршрутизатор и контракт закрыты целиком.

**Состав поставок:**
- **Крючок сессии в Э1** — отклонено: меняет вход модели, а формат выбирает прогон (Э3).
- **Одна поставка на всю серию** — отклонено: ≈ 1 200 строк и три класса оракулов.
- **Карточки и проводка одной поставкой (Э2 + Э3)** — отклонено: ≈ 600 строк уложились бы. Но приёмка данных
  (проверки фактов, судьи, слепой набор) и приёмка поверхности модели с телефоном — разные прогоны и разные люди; сбой
  одной держал бы другую.

**Источники и тесты:**
- **Словарь Snowball целиком фикстурой** — отклонено: тысячи строк сверх предохранителя. Выборка в CI, весь словарь —
  на Mac.
- **Тест, читающий наборы стенда по пути** — отклонено: `env_access` и риск коснуться слепого набора обычным `swift test`.
- **60 карточек стенда базой Э1** — отклонено: без источников, пять — советы безопасности; тестам Э1 хватает восьми
  карточек.

## Risks

- **Бюджет** — выше: порог 780, варианты названы.
- **FTS5 на iPhone не проверен:** самопроверка при прогреве выключит базу с `knowledge.index_failed`; выход — формула
  `bm25` на Swift маленькой поставкой (вопрос ведущему В2).
- **Версии SQLite:** 3.45.1 в CI, 3.54.0 на Mac и телефоне, 3.53.1 у эталона. Паритет P11 на Mac сверяет и счёт; если
  CI на 3.45.1 разойдётся с Mac на примерах P2–P10, это видно красным тестом, а не числом в отчёте.
- **Зависимость от `AllySQLite`:** API обёртки задаёт спека памяти; Э1 берёт только открыть, выполнить, подготовить,
  привязать текст, шагнуть, прочесть число и текст ошибки. Расхождение API — правка Э1, а не второй модуль.
- **Самонахождение в самопроверке** стоит N поисков при загрузке: 300 карточек — ≈ 30 мс на Mac [оценка], на телефоне
  мерит Э3 (P23).
- **Нормализация Юникода на Linux** (swift-corelibs-foundation) может отличаться от Apple. P2 гоняет ударения и «ё» на
  обеих платформах (CI и Mac), самопроверка на телефоне — Э3.
- **Параллельные поставки:** `Package.swift` AllyCore (зависимость и цель), `knowledge/log.md`, `CLAUDE.md` — слияние
  сложением (L35).
- **Правило груб на «моё» и деликатное** — частные случаи по данным чёрного ящика.

## Rollout

Установки нет: пакет без приложения. Мерж — ведущий через `merge_guard.sh`. Карточки Э2 агенты могут писать по
подписанной схеме параллельно с Э1 (стенд `local/spike/erudition/cards/`). Э3 ставит приложение через
`scripts/reinstall_app.sh` отдельным решением родителя.

## Test / eval strategy

- **Метки `// P<n>`:** `StemmerTests` — P1; `EncyclopediaTests` — P2–P10. P11–P12 — строки `eval-smoke.md`, прогон
  `encyclopedia-replay` и `parity.py` на Mac, числа и хэши — в verify-report.
- **Мутации в ту же сессию (П30):**
  - покрытие по всей карточке → P6;
  - без проверки «моё» → P7;
  - без деликатного → P7;
  - буст выключен → P5;
  - синонимы не раскрываются → P4;
  - самопроверка не смотрит первые формулировки → P9;
  - окончание первой группы без проверки «а/я» → P1;
  - запрос «и» вместо «или» → P4: синонимы «кошка», «кот» не находятся вместе с «котик»;
  - веса полей 1 / 1 / 1 вместо 4 / 2 / 1 → P11, сверка счёта на открытых наборах (Mac).
- **Реляционные оракулы:** метаморфное P2 (регистр, знаки, ударения, «ё» на каждой формулировке); самонахождение каждой
  формулировки тестовой базы; дифференциальное P11 (Swift против эталона). Детектор канона знает только hypothesis и
  fast-check — предупреждение разбирается в verify-report, как у прошлых поставок.
- **Покрытие AllyCore ≥ 70%** — по своему `Sources/` (L41). Цель `encyclopedia-replay` тестами не покрыта; её исполняют
  P11 и P12.
