# Plan: «мозг» на iPhone — память и скорость вместе с речью

Уроки архива: **L15** — первый запуск новой подписи требует доверия сертификату на самом
телефоне; это шаг владельца, он вписан в риски, а бюджет памяти зонд читает
`os_proc_available_memory()` на старте. **L17** — каждое число памяти несёт рантайм и режим
загрузки, иначе оно не бюджет. **L19** — sha256 `rules.py` записывается до прогона телефона,
правка проверки — только новым прогоном. **L20** — персона v1 с готовыми фразами оставлена
намеренно: паритет с Mac важнее, персона v2 — отдельный шаг. **L16** — места канона, где живут
числа телефона, собираются поиском (`grep -rn "E4B\|E2B\|LiteRT\|до первого звука"`), а не по памяти.

## Approach

Слайсы, одна рисковая правка на установку (П25):

1. **Модель на телефоне, текст.** Зонд (SwiftUI, Swift 6) и llama.cpp b10809 — xcframework из
   релиза, sha256 сверен с опубликованным (`d6813b3b…`). Это тот же рантайм и те же GGUF-файлы,
   что у бейк-оффа на Mac, поэтому качество сравнимо один к одному. Промпты 40 реплик готовятся
   на Mac через `/apply-template` llama-server; на телефоне — токенизация, кэш префикса персоны
   (П13), сэмплинг и seed бейк-оффа. Память — `phys_footprint` (TASK_VM_INFO) и
   `os_proc_available_memory()` до и после загрузки и пик во время генерации. Режимы загрузки
   записываются: mmap; ленивое чтение строк помеченных тензоров (`lazy_mode` off и on) — для
   обеих моделей. Запуск с Mac — `devicectl device process launch` с аргументами, сбор —
   `devicectl device copy from`.
2. **Голосовая петля.** SpeechAnalyzer и SpeechTranscriber `ru_RU` (системный, вне памяти
   приложения) → модель → AVSpeechSynthesizer с голосом Milena (временный голос) и отметкой
   первого звука. Автоматический прогон: 40 фраз, озвученных `say -v Milena` на Mac, подаются
   в распознаватель файлом. Ручная проверка — родитель говорит в микрофон.
3. **Балласт 1 ГБ** рядом с моделью — запас под Supertonic 3 (пик 956 МБ на iPhone 16 Pro, `KNOWLEDGE.md` §6).
4. **Канон.** Metric с числами телефона, ADR `on-device-model`, `KNOWLEDGE.md` §1, §3, §4, §6, §12,
   индексы и `log.md`.

LiteRT-LM — слайс по условию: E4B не помещается в llama.cpp или медленнее гейта.

## Stack / boundaries

- Зонд — вне git (`local/spike/phone/`), как зонд памяти и стенд бейк-оффа; Swift-гейты
  продукта не оживают (объявления `na-expiry` ждут первой поставки с кодом продукта).
- Подпись — бесплатная Personal Team; bundle id `com.anthonypriceone.allyprobe.big`
  переиспользуется: App ID с `increased-memory-limit` уже выдан, новый App ID из недельного
  лимита бесплатного аккаунта не тратится; зонд памяти на телефоне заменяется новым.
- Модели кладутся в контейнер приложения (`Documents`), а не в бандл: переустановка зонда их не трогает.
- Персона — `persona.ru.md` бейк-оффа (sha256 `37257421…`), сэмплинг — `bakeoff_config.json`.

## Rejected alternatives

- **LiteRT-LM первым** — отклонён для первого слайса, потому что довод `KNOWLEDGE.md` за него
  (эмбеддинги на слой читаются из mmap) есть и в llama.cpp b10809 (`lazy_mode`: строки помеченных
  тензоров читаются по требованию), а llama.cpp даёт паритет с Mac по рантайму и файлам. Возвращается,
  если E4B не помещается или медленнее гейта.
- **Supertonic 3 в этой поставке** — отклонён: ONNX Runtime и русский фронтенд — отдельная
  работа шага 4; память под него проверяется балластом той же величины.
- **Модели в бандле приложения** — отклонён: 3–5 ГБ на каждую переустановку по Wi-Fi.

## Risks

- Доверие сертификату и Developer Mode — шаг владельца (L15); бесплатная подпись живёт 7 дней.
- Запуск с Mac требует разблокированного телефона.
- 8 ГБ моделей по Wi-Fi — минуты; нужно свободное место на телефоне.
- Паритет с Mac — по токенам промпта, не по тексту ответа: Metal на A19 и M5 может выбрать
  другие токены при том же seed, поэтому сравниваются доли по классам.
- Языковой пакет распознавания система качает один раз, до замеров.

## Test / eval strategy

- `eval-smoke.md` — примеры A1–A7 спеки, факт заполняется по прогону.
- Builder ≠ Verifier: `rules.py --selftest` и хэши моделей повторяются до записи чисел.
