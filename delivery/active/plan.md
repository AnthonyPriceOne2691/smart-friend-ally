# Plan: Элли на Mac — приложение для iPhone прямо на Mac (`sim-app`)

Уроки архива (§2.2a):
- **L23, L37** — поддержка языка и платформы — проба в целевой среде, а не строка вендора: диктовку в симуляторе судил
  зонд (ru-RU и en-US — «Model not available»), диктовку macOS — проба 23.10, перегнанная сегодня на macOS 27.2.
- **L10** — шаги скриптов судятся кодом возврата, а не выводом фильтра (`mac_files.py`, `mac_app.sh`, smoke S9).
- **L33, L62** — первый коммит ветки — только `delivery/`: спека и STATUS до кода; знание — вместе с кодом.
- **L7, L16, L70** — граница «данные дочки не покидают контейнер и не видны агентам» живёт в нескольких местах:
  `ops/child-data`, runbook `voice-loop`, новое решение `mac-run`, `repo-map`; места собираются поиском разными словами
  («контейнер», «Containers», «на Mac», «devicectl») и гейтом `okf_sync_gate`, а не по памяти.
- **L46** — снимков экрана нет и на Mac: консоль и окно приложения подтверждает родитель на глаз; агент снимает только
  строки системного журнала без слов (N8, N9).
- **L45** — числа из JSON читаются как Double/Int64 и приводятся явно: байты реестров в плане импорта — `Int64`.
- **L68** — параллельные поставки (`child-open`, `design-demo`, `app-black-box`) трогают `AllyApp.swift`,
  `VoiceLoop.swift` и `voice-loop.md`: своё — новыми файлами, в общих — по строке; при слиянии беру их строки дословно.
- **L80** — что вне git, есть только в одном дереве: зонд, стенд и папка файлов живут в `local/` основного клона и в
  `~/models/ally-mac`; тесты и smoke S9 на них не опираются — временный набор.
- **L34, L52, L61** — бюджет с поправкой +25%: план ≈ 600 → ≈ 750 при стопе 780.
- **L64** — мутации по видимому эффекту: «приёмник пишет и слова» краснит N8 по словам, а не по длине строки;
  «кнопка видна на телефоне» краснит N7; «копия без сверки хэша» краснит N6.
- **L121** — телефонные проверки остаются в сессии теста; эта поставка их не закрывает и не переносит.
- **L14** — после слияния свежего main — строгий `delivery_check --require-ci --diff-base origin/main`.

Не применимы — L44, L59, L60, L69, L71, L72, L73, L81, L82, L89, L98, L99, L100, L105, L111, L112, L129, L130, L134,
L135, L136, L137, L138, L139: звук, сессия, память, подписи и облик не меняются; копия и журнал их путей не трогают.

## Approach

1. **Порядок.** Спека и STATUS (этот коммит) → подпись родителя под N1–N10 → `eval-smoke.md` → код → первый ход на Mac
   (родитель жмёт ⌘R и «Разбудить», агент говорит синтетикой) → verify → handoff в том же PR.
2. **Ядро (`AllyCore`, Linux CI).**
   - `MacImport` — план копии из `manifest.json` и реестров бандла (`ModelRegistry`, `Hearing`, `VoiceSettings`):
     разрешены только `Models/<веса>`, `Models/<Silero>`, `Models/<GigaAM>`, `Voice/<файлы voice.json>`; байты — из
     реестров, sha256 голоса — из `voice.json`, весов и Silero — из списка (его сверил скрипт по пину). Любой чужой
     путь, не тот размер или хэш — отказ целиком строкой для консоли (N4, N5).
   - Копия по плану с подменяемым хэшем: временное имя рядом, сверка байтов и sha256 копии, замена; несошедшийся —
     стоп, старый файл цел (N6). Видимость кнопки — чистая функция (N7).
   - `TraceLine` — приёмник следа: строка `jsonLine()` в переданный вывод; слова отбрасывает расширение `TraceSink`
     (K9), своего `write(_:words:)` у приёмника нет (N8).
   - `VoiceFile` получает `sha256` из `voice.json` (поле уже есть в файле, приложение его не читало).
   - sha256 файла потоком — CryptoKit под `#if canImport(CryptoKit)`, как подпись родителя; тест — на Mac.
3. **Приложение.**
   - `MacFilesButton` (новый файл): кнопка «Файлы с Mac…» и системное окно выбора папки (`fileImporter`, папка);
     показ — по N7. Консоли — одна строка.
   - `VoiceLoop`: импорт в фоне с доступом к выбранной папке (security-scoped), строки в консоль, затем прогрев;
     `TraceLine` с `Logger(subsystem: "com.anthonypriceone.ally", category: "turn")` в той же развилке следа;
     версия `metal` и строка консоли «модель: Metal — <устройство>».
4. **Скрипты.**
   - `scripts/mac_files.py` — раскладка `~/models/ally-mac`, сверка через функции `copy_voice.py`, клоны `cp -c` на
     macOS (иначе обычная копия), `manifest.json`; отказ на `--out` внутри `~/Library/Containers`.
   - `scripts/mac_app.sh` — `xcodegen generate` и проект в Xcode; шаги родителя печатает сам.
   - smoke S9 `delivery/evals/smoke/mac_files_check.sh` — N1–N3 на временном наборе, в `run.sh`.
5. **Знание.** Решение `engineering/mac-run` (симулятор отклонён замером, запуск из Xcode, файлы через приложение,
   журнал `turn`); runbook `voice-loop` — раздел «Элли на Mac» и пути в `implementation:`; `ops/child-data` — контейнер
   на Mac; `repo-map` — входные точки; `index.md`, `log.md`.

## Rejected alternatives (§12.2a)

- **Симулятор iOS 27** — диктовки нет (ассет без задачи «Dictation»), Metal без apple7/metal3, буфер 256 МБ. Отклонён
  замером и решением родителя.
- **Своя сборка llama.cpp b10809 со слайсом симулятора** — нужна была только симулятору.
- **Обёртка `Wrapper/` + `open` или прямой запуск бинаря** — Gatekeeper: «Code did not match any currently allowed
  policy», процесс убит, окно на экране родителя.
- **Копия в контейнер скриптом** — TCC `SystemPolicyAppDataDetailed` отказывает оболочке агентов без окна; обход —
  полный доступ к диску для Терминала — открыл бы данные дочки всему, что запущено в Терминале. Отклонён родителем.
- **Чтение файлов прямо из выбранной папки по закладке** — правит пути весов и голоса во всём приложении; копия в
  контейнер оставляет их как на телефоне.
- **sha256 весов в `model.json`** — правка поверхности модели (§14.4) ради проверки копии; пин уже есть в
  `model_surface.txt`, скрипт сверяет по нему и пишет хэш в список.
- **Устройство Metal из пакета модели** — тоже поверхность модели; приложение видит то же устройство через Metal.
- **Нативное приложение macOS или Mac Catalyst** — другие слайсы и звук мимо `AVAudioSession`: на Mac работало бы не то,
  что на телефоне.
