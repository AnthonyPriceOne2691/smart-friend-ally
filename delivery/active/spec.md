# Spec: голос Элли — Supertonic с ударениями в приложении вместо Milena

> Серия из четырёх поставок под одной подписью: **V1 `voice-onnx`** → **V2 `voice-text`** → **V3 `voice-accent`** →
> **V4 `voice-app`**. Почему серия: вся работа — около 2 300 строк кода и тестов, а предел поставки — 800 строк, по
> правилу переноса ведущего — план не больше 700 (L34, L52). Подпись родителя под этим файлом покрывает примеры всех
> четырёх. В таблице примеров — только V1: гейт ищет её id в тестах этой поставки. Примеры V2–V4 даны списком; каждая
> поставка перенесёт свои таблицей в свою спеку со ссылкой на коммит этой (L51).
>
> Числа — из стендов вне git: `local/spike/tts-swift/` (19.10: Supertonic в Swift на ONNX Runtime, RUAccent в 8 битах) и
> `local/spike/voice-samples/` (22.10: образцы для родителя, замеры). Слова родителя — 22.10 и 23.10, решения ведущего —
> 23.10.

## Problem

На телефоне Элли говорит системным голосом Milena. Родитель 22.10 услышал: ударения неправильные в большинстве слов, тон
не тот, «сильно торопится, быстро говорит, глотает слова». Его решение 22.10 — Supertonic с автоматическими ударениями.
23.10, после первого круга образцов:
- «понравился голос F2, только он очень грубый… нужен тоненький голосок, как у девочки»;
- имя проглатывается: «Привет, это я Эли — то есть не Эли, а Элли»;
- «Она говорила „сегодня“ — прям с Г, а не „сево́дня“, как мы говорим».

Что уже измерено на Mac (фаза 1):
- **Естественность.** Supertonic по машинной оценке естественный: UTMOS 3,8–4,2 против 2,5 у Milena.
- **Ударения.** Со знаком ударения на 60 трудных словах голос верен в 52–53 случаях, без знака — в 33. RUAccent в тексте
  ставит 58 из 60 и 159 из 163 на всём списке. Со словарём на фразах Элли — 98 из 98 слов.
- **Темп.** Скорость по умолчанию 1,05 по предложениям — это темп торопливой Milena: 4,9 слога в секунду против 4,8.
- **Повторы слов.** При скорости синтеза ниже 0,85 Supertonic повторяет слова: 3 случая из 96 при 0,8. Целую фразу из
  нескольких предложений одним вызовом он повторяет уже с 0,95.
- **Нарезка.** Нарезка по запятым ради быстрого первого звука ломает интонацию: кусок кончается падением тона, как
  конец предложения (−4,9 полутона против −5,3), следующий начинается заново выше (+5,1).

## Users / stakeholders

- **Родитель.** Слышит Элли выбранным голосом, с верными ударениями и разговорным произношением. Выбор голоса меняет
  одну строку конфига. Пока файлы голоса не скопированы, приложение работает с Milena, и консоль говорит, чего не хватает.
- **Дочь.** Слышит голос в сессиях при родителе (R).
- **Исполнитель слуха** (Silero VAD и GigaAM через sherpa-onnx). Делит с голосом один ONNX Runtime — пакет `AllyOnnx`.
  Двоичный sherpa-onnx и проверку пары версий он добавит туда своей поставкой.
- **D3.3 `voice-tape`.** Берёт порт проигранного звука Элли для чёрного ящика.
- **Второй круг образцов** (`local/spike/voice-samples-2`). Даёт пресет голоса, запись имени для синтеза и проверенную
  таблицу произношения — данными, без правки кода.

## Решения, на которых стоит серия

1. **Движок — за протоколом `SpeechEngine`:** текст фразы → моно-отсчёты с частотой. Первая реализация — Supertonic 3.
   Если второй круг посоветует другой движок, это будет другая реализация того же протокола.
2. **Один ONNX Runtime на приложение — пакет `Packages/AllyOnnx`.**
   - Двоичный модуль — официальный pod Microsoft `onnxruntime-c` 1.28.0: статический xcframework со слоями iOS,
     симулятора и macOS. Подключается `binaryTarget` по URL с checksum `b503cf59…a327`, лицензия MIT.
   - Поверх — тонкий Swift-слой над C API.
   - Больше никто ORT в приложение не приносит. Пакеты `k2-fsa/sherpa-onnx` и `onnxruntime-swift-package-manager` не
     подключаются: оба тянут свой ORT. Это держит тест-страж.
   - Запасной вариант — сборка `csukuangfj/onnxruntime-libs` 1.28.2, та, что прикрепляет sherpa: замена одной строкой,
     API тот же (28).
3. **Синтез — одна фраза за вызов.**
   - Скорость синтеза не ниже 0,85.
   - 2 потока без spin-wait.
   - Веса в формате external data: ORT отображает их из файла, отпечаток на Mac ≈ 48 МБ вместо 471.
   - Шаги денойзинга — из конфига (по умолчанию 8). Первой фразе можно дать меньше; решает замер на телефоне.
4. **Текст для синтеза — только для синтеза.** На экран и в журнал идёт фраза контракта как есть. Порядок:
   1. ударения RUAccent по исходному написанию;
   2. закреплённый словарь поверх;
   3. переписывание по правилам чтения с переносом ударения;
   4. знак U+0301 на каждом слове от двух слогов, кроме слов с «ё»;
   5. движок.
5. **Произношение и имена — данные в одном файле** (`speech-text.json`). Конкретные записи даёт второй круг. До них —
   правила, названные родителем: «сего́дня» и окончания -ого/-его с исключениями. Имя остаётся «Элли».
6. **Стадия высоты и формант после синтеза — обязательна:** голос F2 сделать «тоньше», по слову родителя 23.10. Способ —
   из конфига:
   - `varispeed` — передискретизация: высота и форманты поднимаются вместе, а синтез идёт медленнее в те же k раз. Чисто:
     UTMOS −0,1 на +2 полутона;
   - `timePitch` — AVAudioUnitTimePitch, только высота;
   - `none`.

   Её цена входит в замер до первого звука. Растягивать звук по времени через AVAudioUnitTimePitch нельзя: UTMOS 2,3,
   уровень Milena.
7. **Пресет голоса — одна строка конфига:** `{"style": "F2+F5:0.5", "semitones": 1.9, "speed": 0.95, "steps": 8}`.
   - По умолчанию «F2+F5 помоложе». 1,9 полутона вместо 2 держат скорость синтеза на 0,851 — не ниже 0,85.
   - Выбор родителя меняет только эту строку.
8. **Веса — не в git.** Supertonic (≈ 380 МБ с external data и стилями голосов) и RUAccent (≈ 90 МБ) лежат в
   `Library/Application Support/Voice`, каталог помечен «не в бэкап».
   - Копируются командой; sha256 сверяется на Mac до копирования.
   - Телефон сверяет размеры.
   - Нет файла или размер не тот — строка консоли и Milena.
9. **Первый звук.** Голос отдаёт время первого прозвучавшего отсчёта первой фразы хода. Это замыкание `firstSound` у
   `PhoneListener`, как у Milena сейчас: из него считается `speech_end_to_sound` (A10).
   - Свои этапы голос кладёт в `TraceStamp.stages`: текст, синтез, сдвиг, старт.
   - Журнал без слов.
10. **Порт проигранного звука.** Отсчёты после стадии сдвига, снятые с микшера, идут в сток по порядку. «Стоп» посреди
    фразы обрезает звук и подаёт знак обрыва. D3.3 кодирует это в AAC.
11. **По запятым не режем.** Первая фраза синтезируется целиком (см. Problem).

## Серия

| Поставка | Что | Где проверяется | План строк |
|---|---|---|---|
| **V1 `voice-onnx`** (эта ветка) | `AllyOnnx` (ORT 1.28.0, слой C API, страж «один ORT») и движок Supertonic в пакете `AllyVoice` за протоколом | Mac: ручная джоба `ios`, как у AllyLlama | ≈ 690 |
| **V2 `voice-text`** | пакет `AllySpeechText`: знаки, закреплённый словарь, правила чтения с переносом ударения, конвейер над протоколом расстановщика | Linux: джоба `swift`, покрытие ≥ 70% | ≈ 480 |
| **V3 `voice-accent`** | RUAccent на Swift: словарь и токенизаторы — Linux; оценщики через `AllyOnnx` — Mac | Linux и Mac | ≈ 680 |
| **V4 `voice-app`** | приложение: голос Supertonic вместо Milena, стадия сдвига, первый звук и этапы в журнал, порт звука, реестр файлов и команда копирования, строка пресета | телефон, в сессии с родителем | ≈ 450 |

Порядок:
- V1 и V2 независимы и могут идти параллельно.
- V3 — после обеих: ей нужны `AllyOnnx` и протокол расстановщика.
- V4 — последней: голос приходит в приложение сразу с полным текстовым путём.
- До V4 у движка нет вызывающего в приложении. Это объявлено (L50), и подключённым он не числится, пока сквозной пример V4
  не пройдёт живым путём.

У каждой поставки своя ветка, свой PR и `merge_guard`. Предохранитель — 800 строк и 25 файлов. Выше 780 — стоп,
`escalation.md` и сразу к ведущему.

## V1 `voice-onnx` — In scope

- **`Packages/AllyOnnx`:**
  - `binaryTarget` ORT 1.28.0 по URL официального pod с checksum;
  - C-модуль, открывающий `onnxruntime_c_api.h`;
  - Swift-слой: окружение — одно на процесс; опции сессии — потоки, spin, уровень графа; сессия из файла с external
    data; тензоры float32 и int64; запуск с именованными входами и выходами; ошибка ORT с текстом;
  - нужные ORT `libc++` и CoreML — `linkerSettings`.
- **`Packages/AllyVoice`:**
  - протокол `SpeechEngine` и тип звука;
  - `SupertonicEngine`: конфиг модели, четыре сессии (duration, encoder, vector estimator, vocoder), цикл денойзинга,
    шум из seed, обрезка по предсказанной длительности;
  - разбор текста Supertonic — шаг в шаг с supertonic-py 1.3.1 на скалярах Unicode, со знаком U+0301;
  - стиль голоса и смесь «F2+F5:w»;
  - пол скорости синтеза 0,85.
- **Страж «один ORT»** `scripts/lint/check_single_ort.sh` — в Linux-джобе `quality`, с отрицательным контролем.
- **Ручная macOS-джоба `ios`:** тесты `AllyOnnx` и `AllyVoice`. Без файлов модели и эталонов — пропуск, видимый в логе
  (П34).

## V1 — Out of scope

- Ударения, словарь, правила чтения (V2, V3).
- Стадия сдвига, воспроизведение, первый звук, порт звука, приложение (V4).
- sherpa-onnx и его проверка пары версий — поставка слуха (L50).

- Скачивание чего-либо приложением.

## V2 `voice-text` — примеры (перенесёт таблицей в свою спеку)

Пакет `AllySpeechText`: только Foundation, Linux. Расстановщик ударений в тестах — двойник по протоколу.

- **Z8 Знаки.** «Привет! Это я, Элли. Что у тебя нового?» с ударениями двойника → «Приве́т! Э́то я, Э́лли. Что у тебя́
  но́вого?». На словах в один слог знака нет, на словах с «ё» тоже: «ёжик» — без знака.
- **Z9 Словарь поверх расстановщика.** Двойник даёт «здоро́во» в «Здорово, что ты это знаешь!» → звучит «здо́рово».
  Запись имени из `speech-text.json` подменяет «Элли» только во входе движка.
- **Z10 Правила чтения с переносом ударения.**
  - «сего́дня» → «сево́дня»;
  - окончания -ого/-его: «но́вого» → «но́вова», «его́» → «ево́», «ничего́» → «ничево́», «того́» → «тово́», «э́того» →
    «э́това», «всего́» → «всево́», «моего́» → «моево́»;
  - исключения не меняются: «мно́го», «немно́го», «стро́го», «до́рого», «убо́го», «поло́го», «ого́»;
  - мутация «исключение не сработало» краснит тест на каждом исключении;
  - «что» → «што», «коне́чно» → «коне́шно», немые согласные, «сч» → «щ», «-тся/-ться» → «-ца» — только строки
    проверенной таблицы второго круга, у каждой строки свой тест.
- **Z11 Перенос ударения.** Знак остаётся на той же гласной: «коне́чно» → «коне́шно», «сего́дня» → «сево́дня».
  Свойство на 500 случайных словах из словаря тестов: число гласных и номер ударной до и после переписывания совпадают.
- **Z12 Порядок.** Двойник расстановщика получает исходное «сегодня», а не «сево́дня»: ударения ставятся до переписывания.
- **Z13 Текст и журнал не меняются.** Экран и `said` показывают «Элли» и «сегодня». В следе хода ни одной кириллической
  буквы. Меняется только вход движка.

## V4 `voice-app` — примеры

- **Z19 Пресет.** Правка строки пресета в `voice.json` меняет голос без кода. Скорость синтеза ниже 0,85 → строка консоли
  «скорость 0,80 ниже 0,85 — взято 0,85».
- **Z20 Файлы голоса.**
  - Нет файла → «голоса нет: скопируй с Mac».
  - Размер не тот → «голос не тот: N байт вместо M».
  - В обоих случаях звучит Milena, ничего не скачивается.
  - Команда копирования сверяет sha256 на Mac до копирования и останавливается на расхождении.
- **Z21 Журнал.** У хода есть этапы `speech_end_to_sound`, `voice_text`, `voice_synth`, `voice_shift`, `voice_start` и
  версии: движок, пресет, ORT. Кириллицы нет.
- **Z22 Бюджет на телефоне**, сессия с родителем, стадия сдвига включена:
  - p95 «конец её речи → первый звук» на 20 ходах ≤ 2,5 с;
  - прирост отпечатка от голоса ≤ 0,4 ГБ: E4B 0,5 + KV 0,45 + голос ≤ 0,4 при лимите 6 ГБ.
- **Z23 Порт проигранного звука.** Сток получает звук после сдвига, по порядку; длительность равна звучанию ± 0,05 с.
  «Стоп» посреди фразы — звук обрывается, приходит знак обрыва.
- **Z24 Стоп.** Тишина ≤ 0,1 с после «Стоп». Начатый синтез отменён, следующий ход звучит.
- **Z25 Паузы.** Между фразами пауза = 0,45 / скорость (0,47 с при 0,95) ± 0,03 с.
- **Z26 На слух** (родитель, сессия): голос телефона — выбранный образец; имя звучит записью второго круга, «сегодня» —
  «сево́дня».

## Non-functional

- **Офлайн.** Продукт не ходит в сеть. Сетевых символов в бинаре нет — судит оракул артефакта.
- **Лицензии**, сверены 23.10 по первоисточникам (L36):
  - ONNX Runtime — MIT (GitHub microsoft/onnxruntime);
  - Supertonic: код — MIT, репозиторий в архиве с 09.09.2026; модель — OpenRAIL-M (карточка HF). Ограничения применения
    — в runbook: не выдавать синтез за человека, не клонировать голоса, не использовать возраст во вред, не давать
    медицинских советов;
  - RUAccent — MIT (HF и GitHub, 22.10).
- **Данные.** Только синтетические фразы. В тестах — «Соня» и «Тёма», детских данных нет. Звуковых эталонов в git нет —
  они лежат в `~/models`.
- **Форма** — по CQG: файл ≤ 500 строк, функция ≤ 50, сложность ≤ 8, без `!`-распаковки. Строки консоли с кириллицей —
  ресурсом (правило `inline_prompt`).
- **Совместимость.** `VoiceOutput`, `PhoneListener` и `TraceStamp` не меняют форму вызовов D1.2 и D2.2.

## Risks

- **ORT 1.28.0 через C API** может разойтись со стендом на ObjC 1.24.2. Z2 и Z3 ловят это первыми. Запасные пути —
  сборка csukuangfj 1.28.2 или ObjC-обёртка той же версии.
- **Объём.** Перенос с Python занижал Swift на 17–43% (L34). Порог переноса задан до кода, в плане.
- **Телефон медленнее Mac.** Стенд оценивал до ×2,5. Бюджет первого звука проверяет Z22. Рычаги: меньше шагов первой
  фразе, сдвиг высоты без замедления синтеза.
- **«е» со знаком может звучать как «э»** (сдвиг слабый, 11%). Проверяет слух родителя (Z26), правится данными.
- **Повторы слов:** при 0,85 и выше в замере — 0 из 96, но не 0 вообще. Ловит журнал и чёрный ящик.
- **Параллельные поставки.** Конфликты при слиянии main — сложением (L35). Минуты CI — пачками; macOS — только ручной
  джобой.
