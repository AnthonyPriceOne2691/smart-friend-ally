# Spec: детская энциклопедия «почему» — Э1 `encyclopedia-core` → Э2 `app-encyclopedia`

> Дорожная карта, п. 5 (`KNOWLEDGE.md` §12). Видение родителя 2026-10-17: эрудиция ребёнка 8–9 лет, речь для пятилетки;
> факты — из базы карточек, а не из головы модели. E4B «по памяти» ошибается в 15% карточек
> ([справка](../../knowledge/references/research/kids-encyclopedia.md)). Слово родителя 2026-10-23: «сейчас собираем,
> оптимизировать будем потом» — минимум тем, без векторов и замеров сверх приёмки.
>
> Две поставки под одну подпись:
> - **Э1** — движок в `Packages/AllyCore` (эта поставка): основы слов, поиск SQLite FTS5 через общий пакет
>   `Packages/AllySQLite`, решение «давать ли подсказку», тесты на Linux;
> - **Э2** — первые 100 карточек и проводка: после «pass» маршрутизатора — поиск, подсказка модели, телефон.
>
> Примеры: P1–P11 — таблицей (Э1), P12–P20 — списком; Э2 перенесёт их таблицей в свою спеку (L33). Буква P свободна во
> всех тест-файлах main и веток (поиск 2026-10-23, L51); приёмка справки E1–E11 перенумерована (таблица в конце).

## Problem

- **Подсказки из базы в продукте нет.** Цель родителя 5 («почему» — не ниже 43 из 48) взята только с верной карточкой,
  подложенной вручную.
- **Движка нет в Swift.** Стенд справки — Python, FTS5, леммы Apple NLTagger. NLTagger нет на Linux CI. Файл SQLite в
  git отбивает гейт данных ребёнка (сигнатура «SQLite format 3»).
- **Базы нет.** У 60 карточек стенда нет проверяемых источников. Пять из них — советы безопасности, вторая копия фраз
  маршрутизатора; одна противоречит заготовке `pii` (велит назвать продавцу мамин телефон).
- **Правило справки не годится для базы из одних карточек.** Вопрос без карточки находит ближайшую чужую: «почему марс
  красный» → светофор. Модель уверенно перескажет чужой факт.

## Э1 `encyclopedia-core` — In scope

1. **Карточка и проверка при загрузке** (схема — ниже). Отказ закрытый: одна негодная карточка выключает всю базу.
2. **Текст:** нижний регистр, «ё» → «е», знаки ударения снимаются. Стоп-слова, глаголы-рамки, вопросительные слова,
   «моё/твоё», деликатные основы, детские синонимы («котик» → «кошка», «кот») — данные `Resources/encyclopedia.json`;
   списки — со стенда справки.
3. **Основы слов — Snowball для русского:** свой перенос алгоритма (BSD-3, сверено `gh api` 2026-10-23), совпадает с
   PyStemmer 3.1.0.
4. **Поиск — SQLite FTS5** через `AllySQLite`. Таблица без содержимого строится в памяти (`:memory:`) при загрузке:
   файла базы нет ни в git, ни на диске. Токены — основы слов. Поля и веса: первая формулировка 4, остальные 2, ответ 1.
   Запрос — «или» по основам с синонимами, `bm25`. Буст первой формулировки — в Swift.
5. **Решение по порядку:** не вопрос → «моё/твоё» → деликатное → нет общего слова → покрытие (строгое правило) →
   подсказка. Подсказка — ответ карточки слово в слово.
6. **Запись решения без слов:** id карточки, правила `knowledge.*`, хэш данных `fnv1a:` (L38).
7. **Самопроверка при загрузке:** негодная карточка или конфиг, или первая формулировка, не нашедшая свою карточку, —
   подсказок нет, `knowledge.selftest_failed`. Таблица FTS5 не создалась — `knowledge.index_failed`.
8. **`encyclopedia-replay`** — исполняемая цель AllyCore, как `discipline-replay`. Вопросы JSONL на stdin, путь к базе
   аргументом, решения в stdout. Для паритета со стендом и слепого набора Э2; набор гоняет ведущий.
9. **Знание:** концепт `engineering/encyclopedia.md` («приложение не зовёт до Э2», `implementation:`). Места «леммы /
   FTS5» — поиском (L16): `product/persona.md`, `KNOWLEDGE.md` §12–§13, индекс справок, `CLAUDE.md`, `knowledge/log.md`.

**Вне Э1:** база карточек и проводка — Э2. Тесты Э1 гоняют тестовую базу из восьми карточек. Вне серии: векторы, алиасы
Викиданных, шумовая модель распознавания, ответ на деликатное (смерть, откуда дети, война) — его держит промпт персоны.

## SQLite и FTS5

- **Один пакет SQLite на приложение — `Packages/AllySQLite`** (решение ведущего 2026-10-23). В нём модуль `CSQLite`
  (`link "sqlite3"`; Linux — `libsqlite3-dev` 3.45.1 образа CI) и тонкая обёртка. Вводит его серия памяти (`memory-core`,
  спека 21d556c). Своего модуля Э1 не заводит: две цели с одним именем не соберутся в одном графе SwiftPM.
- **Порядок.** Пакет в main раньше — Э1 подключает его (+3 строки). Э1 готова раньше — пакет вводит маленькая поставка
  `sqlite-core` по API памяти (вопрос ведущему В1). Внутри Э1 он пробил бы предохранитель.
- **Проба FTS5 2026-10-23** — та же таблица, что у Э1, с запросом `bm25(t, 4, 2, 1)`:

| Где | SQLite | FTS5 | Как |
|---|---|---|---|
| macOS 27, системный (та же версия — в `sqlite3.h` SDK iOS 27) | 3.54.0 | есть, `bm25` работает | скрипт Swift, `import SQLite3` |
| Ubuntu 24.04.5, `libsqlite3-0` 3.45.1-1ubuntu2.8 — версия пакета образа `ubuntu-latest` | 3.45.1 | есть; счёт сошёлся с формулой, посчитанной вручную | контейнер `swift:6.4-noble`, `dlopen`; Debian собирает с `--enable-fts5` |
| iPhone, iOS 27 | 3.54.0 по SDK | не проверено | доводы: SDK; GRDB включает FTS5 по умолчанию при системном SQLite [сторонний, PR #1336] |

- **Нет FTS5 на телефоне** — самопроверка выключает базу (`knowledge.index_failed`, строка консоли в Э2). Выход — та же
  формула `bm25` на Swift по индексу в памяти, ≈ 55 строк: она сверена на пробе вручную. Ставится маленькой поставкой по
  решению ведущего.

## Карточка — одна строка JSONL

| Поле | Что | Где проверяется |
|---|---|---|
| `id` | латиница через дефис, уникален | загрузка |
| `questions` | 3–6 разных формулировок, как спрашивает пятилетка; в каждой — вопросительное слово | загрузка: 3–6 разных; остальное — тест базы (Э2) |
| `answer` | 1–2 предложения: одна причина и один образ. Кириллица и знаки «. , ! : ; — - « » …», ≤ 130 знаков, ≤ 14 слов в предложении, без «я / мне / мой» | загрузка: знаки, предложения, длина; остальное — тест базы |
| `topic` | группа из плана тем | тест базы |
| `key`, `avoid` | регулярное выражение сути для судьи пересказа; известное неверное объяснение (как `check_qa.py`) | тест базы |
| `sources` | ≥ 1: название, URL или ревизия (`oldid`), дата, опорный факт своими словами | тест базы, проверка фактов |
| `license` | `own` — свой текст по фактам | тест базы |

Подсказка «рамка + ответ» ≤ 60 токенов Gemma: рамка справки — 13 токенов, 130 знаков ответа — ≤ 46 токенов
(`llama-tokenize` b10809, самый плотный ответ стенда — 2,83 знака на токен).

## Давать ли подсказку: точность важнее полноты

Неверная подсказка хуже, чем никакой. Промах оставляет ход как сейчас: модель отвечает сама. Замер 2026-10-23: эталон
справки, база — 55 карточек стенда без карточек безопасности, 300 вопросов открытых наборов v1 и v2.

| Правило | С карточкой (90): верно / неверно / нет | Без карточки (178): неверно | Не вопрос (32): ложно |
|---|---|---|---|
| Справки: покрытие ≥ 0,5 по всей карточке | 84 / 2 / 4 | 58 | 2 |
| **Строгое:** значимые слова вопроса — в формулировках карточки; из трёх и больше одно может не найтись | **72 / 1 / 17** | **4** | **1** |
| Строгое на леммах NLTagger | 70 / 0 / 20 | 6 | 1 |

Синоним засчитывается. Ответ в покрытие не входит: «красный» в ответе радуги не делает «почему марс красный» вопросом о
радуге. Пропуски снимают формулировки карточек, а не ослабление правила.

## Э2 `app-encyclopedia` (после мержа Э1)

**База — 100 карточек, по 10 на группу** (карта знаний справки: старшая группа ФОП ДО, «Окружающий мир» 2–3 класса):
звери; птицы, рыбы и насекомые; растения; погода и времена года; небо и космос; земля и вода; тело; как устроен мир
(вода, свет, звук, магнит); машины и техника; люди, время и календарь. Расширение — потом, по пробелам из чёрного ящика.

**В базе нет** тем маршрутизатора (спички, розетка, лекарства, ягоды и грибы «съесть», плита, горячее, нож, окно, вода и
лёд, дорога, собака, дым, боль, потерялась, тело, секрет, чужой, дверь, адрес, страх), деликатных тем и советов «что
делать в опасности».

**Как пишутся карточки** — пишут агенты; брифы и стендовые проверки готовит исполнитель, судей и слепой набор запускает
ведущий:
1. **Писатели** (2 агента по 50) — по брифу: стиль, схема, источники, запретные темы. Источник — ревизия статьи из
   локального корпуса справки (2 948 статей с `oldid`) или URL с датой, факт своими словами. Стендовая проверка
   `check_cards.py` — до нуля ошибок.
2. **Проверка фактов — два независимых прохода** свежих агентов. Они видят вопрос, ответ и источники, но не вердикты друг
   друга. В базу идёт только карточка с двумя «верно»; иначе — переписать или выбросить.
3. **Слепые судьи** (два свежих агента Claude) по критериям родителя: безопасность с запретом > ум > живость. Лист без id и
   ключей, вердикт считает код.
4. **Слепой набор v3** пишет свежий агент, когда база окончательна. Хэш — до прогона, счёт один раз, только суммы.
   Исполнитель набор не открывает; провал — правка по открытым наборам и новый набор (L49).

**Проводка:**
- на «pass» маршрутизатора `Session` спрашивает энциклопедию; на `script`, `guard`, `forget` — нет;
- с подсказкой ход в режиме `why` (до трёх предложений, без вопроса в конце), без подсказки — `talk`, как сейчас;
- след хода получает `knowledge` на всех обёртках, включая `Conversation` (L58);
- приложение грузит базу при прогреве, в консоли — число карточек или отказ самопроверки.

**Формат подсказки (правило записано до прогона):**
- **A** — строка «Подсказка к вопросу девочки — верный ответ: <ответ>» перед её фразой в реплике пользователя;
- **B** — та же строка после её фразы, если A не прошёл;
- **C** — системная реплика, если не прошёл и B (правит `LlamaModel` — рисковый путь `Packages/AllyLlama/`).

Формат проходит, если на `er` (16 вопросов × seed 42, 43, 44) верных ≥ 43 из 48 с настоящим поиском и артефактов 0.
Артефакт — «подсказк» в ответе или «ты права / верно / правильно» в первой фразе, ловит регулярное выражение. Стенд: Mac,
llama.cpp b10809, E4B Q4_K_M, персона v2.4 — в ней уже есть «иногда ниже бывает подсказка к её вопросу». Не прошёл ни
один — стоп и `escalation.md`.

**Ожидания Э2:**
- **P12** База: 100 карточек, по 10 на группу. Тест всей базы в CI: правила схемы, лицензия `own`, источник есть.
- **P13** Каждая формулировка находит свою карточку с подсказкой — 100%. Маршрутизатор на каждой формулировке и ответе —
  `pass`. Деликатных основ нет.
- **P14** Факты — два «верно» на всех карточках. Судьи: провалов безопасности 0; «верно и понятно пятилетке» — да у обоих
  на ≥ 95%.
- **P15** Ни одной последовательности из восьми слов, общей с абзацами Википедии корпуса. Подсказка ≤ 60 токенов Gemma
  на каждой карточке.
- **P16** Слепой набор v3, 100 вопросов: 40 с карточкой (половина с шумом распознавания), 40 без, 20 не-вопросов и
  «моё». С карточкой верных ≥ 28, неверных ≤ 2; без карточки неверных ≤ 2; на не-вопрос ложных ≤ 1.
- **P17** Через настоящую `Session`: «почему небо голубое» → подсказка, режим `why`, `knowledge.hint`; «Дай мне спички» и
  её адрес — поиска нет; «где мой мишка» → `talk`, `knowledge.personal`. Без подсказки модель получает реплику байт в
  байт как раньше. Мутация «поиск до маршрутизатора» краснит пример.
- **P18** Формат по правилу выше: `er` ≥ 43 из 48, артефактов 0.
- **P19** Поверхность модели (§14.4): в снимке — карточки, конфиг и код подсказки. Ходы без подсказки не меняются (P17).
