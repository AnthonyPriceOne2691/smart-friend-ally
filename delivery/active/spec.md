## Problem

V2 дала конвейер текста для синтеза над протоколом `StressPlacer`, но настоящего расстановщика на телефоне нет: в тестах
— двойник. RUAccent (turbo3.1 int8, tiny mode, «поняла») на Python ставит 159 из 163 позиций списка стенда, со словарём
на фразах Элли — 98 из 98; на телефоне Python нет, нужен Swift поверх общего ONNX Runtime (`Packages/AllyOnnx`, V1).

## In scope

- Реализация `StressPlacer` (V2): нормализация и разбиение текста как в RUAccent 1.5.8.3, словари tiny mode (111 тыс.
  форм, омографы, «ё»), три токенизатора (посимвольный, WordPiece со смещениями, byte-level BPE с 10 007 добавленными
  токенами), решения «ё», омографов и модели слов; три модели через `AllyOnnx` (омографы turbo3.1 int8, «ё», модель
  слов).
- Словари и токенизаторы — данные из `~/models/tts/ruaccent` (вне git, копируются командой V4); эталоны Python — в
  `~/models` рядом.

## Out of scope

- Приложение и голос в нём — V4; модель «использования ударения» и правиловый движок — не в tiny mode.

## Non-functional

- Офлайн; данные — только фразы стенда и вымышленные «Соня», «Тёма», «Мурка».
- Форма по CQG: файл ≤ 500 строк, функция ≤ 50, сложность ≤ 8, без `!`-распаковки.
- Предохранитель: 800 строк; план с поправкой +50% (слово ведущего 2026-10-23); выше 780 — стоп и доклад.
