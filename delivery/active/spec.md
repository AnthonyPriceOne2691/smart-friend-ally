# Spec: детская энциклопедия «почему» — серия Э1 `encyclopedia-core` → Э2 `encyclopedia-cards` → Э3 `app-encyclopedia`

> Дорожная карта, п. 5 (`KNOWLEDGE.md` §12): проверенные ответы и поиск по словам. Видение родителя 2026-10-17: эрудиция
> любопытного ребёнка 8–9 лет, речь для пятилетки. Факты берутся из базы карточек, а не из головы модели: E4B «по памяти»
> ошибается в 15% карточек и отвечает расплывчато в 34% ([справка](../../knowledge/references/research/kids-encyclopedia.md)).
>
> Серия из трёх поставок под одну подпись. **Э1** — движок в `Packages/AllyCore`: основы слов, поиск SQLite FTS5 через общий
> пакет приложения `Packages/AllySQLite`, решение «давать ли подсказку», тесты на Linux (эта поставка). Пакет SQLite вводит
> серия памяти (раздел «SQLite и FTS5»). **Э2** — первые 300 карточек: две независимые проверки фактов, слепые судьи по
> критериям родителя, слепой набор вопросов. **Э3** — проводка: после «pass» маршрутизатора — поиск, подсказка модели в
> режиме `why`; формат подсказки выбирает прогон на стенде по правилу ниже. Примеры: P1–P12 — таблицей (Э1), P13–P19 и
> P20–P25 — списком, Э2 и Э3 перенесут их таблицей в свои спеки со ссылкой на коммит этой (L33). Буква P свободна во всех
> тест-файлах main 8f938a6 и всех веток (поиск 2026-10-23, L51); E занята пробами маршрутизатора, поэтому приёмка справки
> E1–E11 перенумерована (раздел «Приёмка справки → P»).
>
> Замер 2026-10-23 на стенде (`local/spike/erudition/analysis/`, вне git): на базе из одних карточек правило справки даёт
> неверную подсказку на трети вопросов, для которых карточки нет. Отсюда строгое правило (раздел «Давать ли подсказку»).

## Problem

- **Факты «из головы» модели неверны в 15% случаев.** Цель родителя 5 («почему» с подсказкой — не ниже 43 из 48) взята
  только с подсказкой, которую подкладывали вручную: верная карточка на каждый вопрос. Поиска в продукте нет.
- **Движка нет в Swift.** Стенд исследования — Python, SQLite FTS5 и леммы Apple NLTagger. На Linux CI нет NLTagger, а
  файл SQLite в git отбивает гейт данных ребёнка (правила `data-ext` и `data-magic`, сигнатура «SQLite format 3»): готовую
  базу не положить в репозиторий файлом. Справка не проверила FTS5 и NLTagger на iPhone.
- **Базы нет.** У 60 карточек стенда нет проверяемых источников — только «стандартный факт детских энциклопедий». Пять из
  них — советы безопасности, вторая копия подписанных фраз маршрутизатора. Одна из них ей противоречит: «потерялась»
  велит назвать продавцу мамин телефон, а заготовка `pii` — «адрес и телефон говорят только маме, папе и знакомым
  взрослым».
- **Правило справки не переносится на базу из одних карточек.** Справка мерила смешанный корпус: 60 карточек и 2 948
  абзацев Википедии. Вопрос без карточки там находил свою статью. В базе из одних карточек он находит ближайшую чужую
  карточку: «почему марс красный» → светофор, «зачем нам брови» → слёзы. Модель уверенно перескажет чужой факт.

## Users / stakeholders

- **Дочь:** на «почему небо голубое?» Элли отвечает верно и просто, с образом, своими словами по проверенной карточке.
  На вопрос без карточки Элли отвечает сама, как сейчас. На «моё», деликатное и не-вопрос подсказки нет.
- **Родитель:** факты берутся из базы с источниками и двумя проверками. База коммерчески чистая: только свой текст. В следе
  хода видно, какая карточка подсказала, слов в нём нет. Ошибку факта видно в чёрном ящике.
- **Следующие поставки:** Э2 (база), Э3 (сессия и приложение), память (может взять основы слов), разбор чёрного ящика
  (пробелы → новые карточки).

## Э1 `encyclopedia-core` — In scope

1. **Карточка и её проверка при загрузке** (схема — ниже). Отказ закрытый: одна плохая карточка выключает всю базу.
2. **Текст:** нижний регистр; «ё» → «е»; знаки ударения U+0301 и U+0300 снимаются; слова — буквы и цифры. Стоп-слова,
   глаголы-рамки («берётся», «бывает»), вопросительные слова, слова «моё/твоё», деликатные основы, детские синонимы
   («котик» → «кошка», «кот») — данные `Resources/encyclopedia.json` одной копией. Списки и синонимы — из стенда
   исследования, свой текст.
3. **Основы слов — Snowball для русского:** свой перенос опубликованного алгоритма на Swift. Лицензия BSD-3, сверено
   `gh api` 2026-10-23: snowballstem/snowball и snowball-data. Основы совпадают с эталонной реализацией PyStemmer 3.1.0.
4. **Индекс и поиск — SQLite FTS5** через общий пакет `Packages/AllySQLite`. Таблица FTS5 без содержимого
   (`content=''`, `detail=full`, токенизатор `unicode61 remove_diacritics 0`) строится в памяти (`:memory:`) при загрузке
   из байтов карточек. Файла базы нет ни в git, ни в бандле, ни на диске. Токены — основы слов, приготовленные заранее, как
   на стенде. Поля: первая формулировка, остальные формулировки, ответ; запрос — «или» по разным основам с синонимами,
   ранжирование `bm25(…, 4, 2, 1)`. Буст первой формулировки считает Swift: счёт × (1 + доля её основ, найденных в запросе).
5. **Решение «давать ли подсказку»** — по порядку: не вопрос → «моё/твоё» → деликатное → ни одного общего слова →
   покрытие (строгое правило, ниже) → подсказка. Текст подсказки — ответ карточки слово в слово.
6. **Запись решения без слов:** id карточки, правила `knowledge.*`, хэш данных `fnv1a:` (FNV-1a конфига и карточек, L38).
7. **Самопроверка при загрузке:** любая негодная карточка или конфиг, или карточка, чья первая формулировка не находит
   саму себя с подсказкой, — подсказок нет совсем, правило `knowledge.selftest_failed`, `healthy == false`. Таблица FTS5
   не создалась — то же, правило `knowledge.index_failed`: отказ называет себя (П33).
8. **Инструмент `encyclopedia-replay`** (исполняемая цель AllyCore, как `discipline-replay`). Вход — JSONL вопросов на
   stdin, путь к базе — аргументом. Выход — решения в stdout (подсказка или нет, карточка, правила, тройка лучших), время —
   в stderr. Нужен для паритета со стендом (P11, P12) и для слепого набора Э2, который гоняет ведущий.
9. **Знание:** концепт `engineering/encyclopedia.md`: движок, правило, схема, «приложение движок не зовёт до Э3»,
   `implementation:`. Места «леммы / FTS5», найденные поиском (L16): `product/persona.md`, `KNOWLEDGE.md` §12–§13, индекс
   справок, `CLAUDE.md` (на сдаче), карта репозитория, `knowledge/log.md`.

## Э1 — Out of scope

- **База карточек** — Э2. Тесты Э1 гоняют тестовую базу из восьми карточек (таблица ниже).
- **Крючок сессии, режим `why`, подсказка в промпте, загрузка из бандла, телефон** — Э3.
- **Векторный поиск** — только если промахи на детских вопросах из чёрного ящика будут больше 10% (решение 2026-10-17).
  Также вне серии: алиасы Викиданных, doc2query, шумовая модель распознавания (у маршрутизатора она есть, у энциклопедии
  нет: точность важнее полноты), проверка фактов E4B на телефоне.
- **Ответ на деликатное** (смерть, откуда дети, война) — промпт персоны (advisory). Тема маршрутизатора для него будет по
  данным чёрного ящика. Энциклопедия на такие вопросы просто молчит.

## SQLite и FTS5: общий пакет и проба

- **Один пакет SQLite на приложение — `Packages/AllySQLite`** (решение ведущего 2026-10-23). В нём:
  - системный модуль `CSQLite` (`link "sqlite3"`; на Mac и iPhone — SQLite из SDK, на Linux — `libsqlite3-dev` 3.45.1
    образа `ubuntu-latest`);
  - тонкая обёртка Swift: открыть, подготовить, привязать, шагнуть, ошибки.

  Вводит его серия памяти: `memory-core`, ветка `feat/memory-core`, спека 21d556c. Э1 своего модуля SQLite не заводит: два
  модуля с одним именем цели не соберутся в одном графе SwiftPM. От обёртки Э1 нужно: база в памяти, выполнить SQL,
  подготовить запрос, привязать текст, шагнуть, прочесть целое и дробное, текст ошибки.
- **Порядок.** Если пакет в main раньше реализации Э1, Э1 только подключает его. Если Э1 готова раньше, пакет по тому же
  API вводит отдельная маленькая поставка `sqlite-core` (≈ 130 строк с тестами и проводкой CI). Внутри Э1 он не помещается
  в предохранитель: ≈ 690 строк по плану, ≈ 860–900 с поправкой движка. Решает ведущий (вопрос ведущему в `decisions.md`).
- **FTS5 проверен пробой 2026-10-23.** Таблица — как у Э1: три поля, `content=''`, `unicode61 remove_diacritics 0`, запрос
  «или» и `bm25(t, 4, 2, 1)`.

| Где | SQLite | `ENABLE_FTS5` | Таблица и `bm25` | Как проверено |
|---|---|---|---|---|
| macOS 27, системный SQLite; та же версия 3.54.0 — в `sqlite3.h` SDK iOS 27 | 3.54.0 | 1 | работают | скрипт Swift с `import SQLite3`, `DEVELOPER_DIR` Xcode |
| Linux: Ubuntu 24.04.5, `libsqlite3-0` 3.45.1-1ubuntu2.8 — та же версия пакета, что `libsqlite3-dev` образа `ubuntu-latest` | 3.45.1 | 1 | работают; счёт сошёлся с формулой, посчитанной вручную (−0,5844 и −0,9188 на пробе из трёх документов) | контейнер `swift:6.4-noble` (arm64), библиотека через `dlopen`; сборка Debian — с `--enable-fts5` (правила Debian sqlite3 3.46.1, зеркало, `gh api`) |
| iPhone, iOS 27 | 3.54.0 по SDK | не проверено | не проверено | рантайма симулятора на Mac нет, телефон — только с ведущим. Довод: GRDB с v6.7.0 включает FTS5 по умолчанию при системном SQLite [сторонний, PR #1336, `gh api`] |

- **Если FTS5 нет** (на телефоне или в будущем образе CI), самопроверка не создаёт таблицу: подсказок нет, правило
  `knowledge.index_failed`, в Э3 — строка консоли. Тихо неверного поиска не бывает. Выход — та же формула `bm25` на Swift
  по индексу в памяти, ≈ 55 строк. Формула FTS5 сверена на пробе Linux вручную: частота × вес поля, длина документа по всем
  полям, IDF с нижней границей 1e−6. Ставится маленькой поставкой по решению ведущего; второй дорожки кода заранее не
  держим. Проба на телефоне — P23 (Э3).

## Карточка — одна строка JSONL

| Поле | Что | Проверка |
|---|---|---|
| `id` | латиница через дефис, уникален: `sky-blue` | загрузка (Э1) |
| `questions` | 3–6 разных формулировок так, как спрашивает пятилетка; в каждой — вопросительное слово | загрузка: 3–6 разных; вопросительное слово — тест базы (Э2) |
| `answer` | 1–2 предложения: одна причина и один образ из того, что ребёнок видел, трогал или ел. Только кириллица, пробелы и знаки «. , ! : ; — - « » …», не длиннее 130 знаков; по 14 слов в предложении, без «?», без «я / мне / мой» | загрузка: знаки, предложения, длина; остальное — тест базы (Э2) |
| `topic` | группа из плана тем (Э2) | тест базы |
| `key` | регулярное выражение сути, по которому судья узнаёт верный пересказ (как в `check_qa.py` и `erudition_rules.py`) | тест базы: компилируется; нижний регистр без «ё»; ловит свой ответ; не ловит пустую строку, отговорки, свои формулировки и `avoid` |
| `avoid` | известное неверное объяснение («небо отражает море») | тест базы |
| `sources` | ≥ 1: название, URL или ревизия статьи (`oldid`), дата обращения, опорный факт своими словами — без цитат | тест базы; судьи фактов (Э2) |
| `license` | `own` — свой текст по фактам; другой лицензии в базе нет | тест базы |

Подсказка «рамка + ответ» укладывается в 60 токенов Gemma. Рамка справки «Подсказка к вопросу девочки — верный ответ: » —
13 токенов, ответу остаётся 47. 130 знаков ответа — ≤ 46 токенов даже у самого плотного ответа стенда: 2,83 знака на
токен. Мерил `llama-tokenize` b10809 на словаре закреплённого GGUF (замер 2026-10-23). На стенде ответы — 32–50 токенов,
с рамкой — 43–62, три карточки длиннее 60. Точное число на каждой карточке меряет Э2 на Mac (P19); в CI — предел знаков.

## Давать ли подсказку: точность важнее полноты

Неверная подсказка хуже, чем никакой: модель уверенно перескажет чужой факт. Промах же ничего не ломает — модель
отвечает сама, как сейчас. Замер 2026-10-23: эталон справки (Snowball, синонимы, рамки, буст), база — 55 карточек стенда
(60 без пяти карточек безопасности), 300 вопросов открытых наборов v1 и v2.

| Правило | С карточкой (90): верно / неверно / нет | Без карточки (178): неверно | Не вопрос (32): ложно |
|---|---|---|---|
| Справки: покрытие ≥ 0,5 по всей карточке (с ответом) | 84 / 2 / 4 | **58** (33%) | 2 |
| **Строгое:** все значимые слова вопроса — в формулировках карточки; из трёх и больше одно может не найтись | 72 / 1 / 17 | **4** (2%) | 1 |
| Строгое на леммах Apple NLTagger вместо Snowball | 70 / 0 / 20 | 6 | 1 |

Значимые слова — без стоп-слов и рамок. Синоним засчитывается («котик» в вопросе, «кошка» в формулировке). Ответ в
покрытие не входит: его слова объясняют причину, а не повторяют вопрос. В ответе радуги есть «красный», но «почему марс
красный» — не про радугу. Леммы не лучше основ ни по полноте, ни по точности. Пропуски строгого правила снимают
формулировки в карточках, а не ослабление правила: «почему кошки мурлычут» Snowball не сводит к «мурлычет» — значит, в
карточке нужна и такая формулировка.

## Acceptance (observable) — Э1

Тесты AllyCore на Linux (системный SQLite 3.45.1 с FTS5) доказывают:
- основы слов совпадают с Snowball;
- решение не меняется от регистра, знаков, ударений и «ё»;
- детские слова находят свою карточку, соседние карточки не путаются;
- на чужое по смыслу, не-вопрос, «моё» и деликатное подсказки нет;
- негодная база и несозданная таблица FTS5 не дают ни одной подсказки;
- в записи решения нет ни одного слова реплики.

На Mac Swift совпадает с эталоном на Python на всех вопросах открытых наборов.

## Э2 `encyclopedia-cards` (после мержа Э1)

**База — 300 карточек** по карте знаний: старшая группа ФОП ДО и «Окружающий мир» 2–3 класса

персоны и темы открытых наборов v1 и v2.

**Чего в базе нет:**
- темы маршрутизатора (спички, розетка, лекарства, химия, ягоды и грибы «съесть», плита, горячее, нож, окно, вода и лёд,
  дорога, собака, дым, боль, потерялась, тело, секрет, интернет, чужой, дверь, адрес, «ты живая?», страх);
- деликатные темы (смерть, откуда дети, война, тяжёлые болезни, вера, ссоры родителей);
- советы «что делать в опасности» — карточка объясняет мир, а безопасность держит маршрутизатор.

Пять карточек безопасности стенда в базу не идут (вопрос 4).

**Как пишутся карточки.** Карточки пишут агенты. Файлы для них готовит исполнитель, судей и слепой набор запускает ведущий.

1. **Писатели** (6 агентов по 50 карточек, по одной-две группы) работают по `cards-brief.md`: стиль, схема, источники,
   запретные темы, три образцовые карточки. Писатель проверяет свою партию стендовой проверкой `check_cards.py` до нуля
   ошибок. Она судит правила схемы, `discipline-replay router` (ответ «pass») и пересечение текста с абзацами Википедии.
   Источник факта — ревизия статьи из локального корпуса справки (название и `oldid`, 2 948 статей с ревизиями) или другая
   надёжная страница (URL и дата). Опорный факт пересказан своими словами.
2. **Проверка фактов — два независимых прохода F1 и F2:** свежие агенты по `facts-brief.md`. Они видят вопрос, ответ и
   источники — без `key`, `avoid`, рассуждений писателя и вердиктов друг друга. Вердикт на карточку: верно / неточно /
   неверно / не подтверждено, с проверенным утверждением и открытым источником. F2 по возможности берёт второй источник.
   Карточка идёт в базу только с двумя «верно»; иначе — переписать и снова оба прохода, или выбросить. Вердикты — в
   `delivery/active/facts-F1.jsonl` и `facts-F2.jsonl`: id, вердикт, заметка; данных ребёнка в них нет.
3. **Слепые судьи J1, J2 по критериям родителя** (безопасность с запретом > ум > живость) — свежие агенты Claude, не Gemma.
   Лист: перемешанные «вопрос → ответ» без id, ключей и источников. Атомарные вопросы: опасный совет или поощрение
   опасного? деликатная тема? верно ли для пятилетки? понятно ли? есть ли живой образ? Вердикт считает код
   (`score_judges.py`), согласие судей и каппа — в отчёте.
4. **Механика:** тесты базы в CI (P13–P15) и стендовые проверки (P19).
5. **Слепой набор v3** (P18) пишет свежий агент по `v3-brief.md`, когда база окончательна. Набор замораживается хэшем до
   первого прогона, ведущий считает его один раз инструментом, печатающим только суммы по классам (`score_v3.py`).
   Исполнитель его не открывает. Провал — правка только по открытым наборам и новый слепой набор v4 другого агента (L49).

## Э3 `app-encyclopedia` (после мержа Э2)

1. **Сессия:** на «pass» маршрутизатора `Session` спрашивает энциклопедию. На `script`, `guard` и `forget` не спрашивает.
   С подсказкой ход идёт в режиме `why` (до трёх предложений, до 50 слов, без вопроса в конце), подсказка доходит до модели
   в формате, выбранном прогоном. Без подсказки — `talk`, как сейчас.
2. **След хода** получает `knowledge`: карточку, правила и хэш, без слов. Чёрный ящик берёт поля следа как есть. Новое
   поле проверяется на всех обёртках, включая `Conversation` (L58).
3. **Приложение** грузит базу из бандла AllyCore при прогреве. В консоли — «энциклопедия: 300 карточек» или строка отказа
   самопроверки.
4. **Поверхность модели** (§14.4): в снимок входят карточки, конфиг (правило и рамка) и код, собирающий подсказку. Нужен
   дифференциальный прогон против текущей поверхности и оракул §6.5b «обратная сторона»: с подсказкой суть карточки
   появляется в ответе. Строка реестра `safety-below-model.md` — «на почему — настоящая причина» с частичным
   исполнителем.
5. **Формат C** правит `LlamaModel` — это рисковый путь `Packages/AllyLlama/` (объявлен D1.2), единственный в поставке.

**Правило выбора формата (P21), записано до прогона.** Кандидаты:

Персона v2.4 уже говорит: «Иногда ниже бывает подсказка к её вопросу — это верный ответ: перескажи его своими словами».
Стенд: Mac, llama.cpp b10809, E4B Q4_K_M, персона v2.4, сэмплинг `model.json`, seed 42, 43, 44. Только открытые наборы:

## Non-functional

- **Без сети и новых внешних зависимостей:** SQLite — системный, через общий пакет проекта `AllySQLite`; NaturalLanguage
  не берётся, Snowball — свой перенос. AllyCore — Foundation, `Discipline` и `AllySQLite`, собирается и тестируется на
  Linux, покрытие ≥ 70% (джоба `swift`).
- **Данные:** в тестах — только «Соня», «Тёма», «Мурка». Карточки — факты о мире, данных ребёнка в них нет. Слепой набор
  v3 — вне git. База SQLite — только в памяти процесса: ни файла, ни спутников (`-wal`, `-journal`) ни в дереве, ни на
  диске телефона.
- **Форма:** файл ≤ 500 строк, функция ≤ 50, сложность ≤ 8, без `!`-распаковки. Русские тексты и списки — в ресурсах
  (правило `inline_prompt`). Числа из JSON — явными типами (L45).
- **Предохранитель — на каждую поставку:** 800 строк, 25 файлов, рисковых путей ≤ 1.
  - Э1 — план ≈ 560 строк в 10 файлах при `AllySQLite` в main. Поправка движка +25–31% (L58, L61) даёт ≈ 700–735.
    Стоп на 780.
  - Э2 — ≈ 380: из них 300 строк — карточки, по строке JSONL на карточку (данные длинными строками, как `router.json`).
  - Э3 — ≈ 210, с форматом C ≈ 260.

## Risks

- **Полнота строгого правила:** 17 из 90 вопросов с карточкой на открытых наборах остаются без подсказки. Это снимают
  формулировки (в том числе формы числа и лица: «кошки мурлычут») и синонимы. Мерит слепой набор v3, а не открытые
  (L49).
- **Snowball не сводит формы глагола** («мурлычет» и «мурлычут» — разные основы). Леммы Apple по замеру не лучше
  (70 против 72 верных), поэтому формы закрывают данные карточек.
- **Foundation на iOS и на Linux** могут по-разному понижать регистр и нормализовать Юникод. Самопроверка при загрузке на
  телефоне (Э3) выключит базу, а не даст тихо неверный поиск.
- **FTS5 на iPhone не проверен:** есть на macOS 27 и в Linux образа CI (проба 2026-10-23), довод для iOS — тот же SQLite
  3.54.0 в SDK и GRDB. Отказ виден сразу: самопроверка не создаёт таблицу (`knowledge.index_failed`), выход — формула
  `bm25` на Swift (раздел «SQLite и FTS5»).
- **Версии SQLite разные:** 3.45.1 в CI, 3.54.0 на Mac и телефоне, 3.53.1 у эталона. Формула `bm25` одна; паритет P11 на
  Mac сверяет решения, тройку и счёт, метаморфное P2 и примеры гоняются и в CI на 3.45.1.
- **Порядок с `AllySQLite`:** Э1 зависит от пакета серии памяти. Опоздание пакета — поставка `sqlite-core` по тому же API
  (решает ведущий); свой модуль SQLite Э1 не заводит.
- **Бюджет** (L34, L41, L52, L58, L61): движки выходили на 25–31% выше плана. Стоп на 780 — `escalation.md` и сразу к
  ведущему, варианты — в плане.
- **Деликатный список груб:** «почему пчела умирает, когда ужалит» (v2) остаётся без подсказки. Цена принята: дешевле
  промаха с карточкой про смерть.
- **«Моё» груб:** «почему мой котик мурлычет» без подсказки (правило справки). Частные случаи — по данным чёрного ящика.
- **Неверный факт в карточке** уверенно перескажет модель. Держат две проверки, судьи и чёрный ящик.
- **Лицензии** (L36): Snowball — BSD-3 (сверено), карточки — свой текст, источники только названы. Текст Википедии
  (CC BY-SA), OpenStax (CC BY-NC-SA) и страниц NASA и NOAA (статус не подтверждён) в базу не попадает (P19).
