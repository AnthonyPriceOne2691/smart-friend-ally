## Problem

Конвейер V2 работает над протоколом `StressPlacer`, но в тестах там двойник — настоящего расстановщика нет. RUAccent
1.5.8.3 (tiny mode, омографы turbo3.1 int8, «поняла») на Python ставит 159 из 163 позиций списка стенда. Чтобы Swift
дал тот же текст, логику Python нужно перенести дословно, вместе с причудами:
- омографы с нечётным числом гипотез идут другим путём;
- группы гипотез больше трёх режутся;
- метки модели «ё» ложатся на слова по номеру;
- знак модели слов ставится на букву раньше позиции.

Выходы моделей при этом приходят извне.

## In scope

1. **Текст.**
   - Фильтр символов — регулярка `normalize` RUAccent.
   - Предложения: расстановщик получает одну фразу контракта за вызов (V2, V4). Внутри — простое разбиение по концам
     предложений; правила сокращений razdel не переносятся. Все 163 фразы стенда razdel видит одним предложением.
   - Слова и промежутки: `split_by_words`, с « - » → « ~ ».
   - Склейка, `delete_spaces_before_punc`, `fix_capital`.
2. **Словари.** Читаются из простых JSON-файлов: команда V4 распаковывает `.gz` на Mac, потому что в Foundation на Linux
   нет gzip.
   - `accents_nn` — 110 826 форм, плюс «о» → «+о».
   - `omographs` — 19 741, плюс «коса» и закреплённое «поняла» → «понял+а».
   - `yo_words` — 85 568.
   - `yo_homographs` — 637.
3. **Решения — как в Python.**
   - **«ё»:** сначала `yo_words`. Затем модель «ё» — только если во фразе есть «е»: логиты токенов → softmax → токены
     без служебных; подслово определяется по длине токена, у неизвестного свой путь; среднее по подсловам → метка
     слова. Метка ложится на слово RUAccent с тем же номером, `yo_homographs`.
   - **Омографы:** текст с `<w>…</w>` на каждую гипотезу. Если у всех омографов фразы чётное число гипотез — пары,
     сравнение логита «верно» (softmax по всему пакету). Если хоть у одного нечётное — `group_words`: особые слова
     тройками, чётные группы больше трёх парами, `transfer_grouping`, softmax по строке. Ответы ложатся на найденные
     омографы по порядку, даже когда их число не совпало.
   - **Модель слов** — для слова не из словаря, без пунктуации, от двух гласных: логиты позиций → argmax и максимум
     softmax → «+» перед буквой с номером позиции минус один при оценке ≥ 0,55. Метки `NO` и `STRESS_SECONDARY`
     пропускаются.
   - **Путь словаря:** перенос «+» на исходное написание — цикл Python как есть.
4. **Протокол моделей `AccentModels`** (стык ведущего 2026-10-23):
   - `omograph(Encoding) → [Float]` — логиты `[2]`, индекс 1 — «гипотеза верна»;
   - `yo(Encoding) → [[Float]]` — метки NO_YO, PUNCT, YO;
   - `accent(Encoding) → [[Float]]` — метки NO, STRESS_PRIMARY, STRESS_SECONDARY;
   - одна гипотеза — один вызов; softmax и выбор — логика V3b;
   - реализует V3c через `AllyOnnx`; `Encoding` и токенизаторы — V3a.
   Логика получает токенизаторы через свой протокол: в тестах их заменяет двойник с записанной разметкой — файлов
   токенизаторов в CI нет.
5. **`RuAccentPlacer: StressPlacer`** — в таргете `AllyAccent` пакета V3a (только Foundation, Linux) с зависимостью на
   `../AllySpeechText`. Готов, но до V4 не подключён (L50).

## Out of scope

- Токенизаторы (V3a), модели через `AllyOnnx` (V3c), приложение (V4).
- Правила сокращений razdel, модель «использования ударения» и правиловый движок (их нет в tiny mode).

## Acceptance examples — доля V3b в Z14–Z16 (логика по записанным выходам моделей)

| id | Дано | Ожидание | Оракул |
|---|---|---|---|
| Z14 | 163 фразы списка стенда без имён; выборка словарей, записанная разметка токенизаторов и логиты всех вызовов моделей Python (turbo3.1 int8, tiny mode, «поняла») | текст `RuAccentPlacer` равен тексту Python в 163 из 163 | `RuAccentReplayTests` (Linux, фикстура < 512 КБ из записи V3a в `~/models/tts/ruaccent-parity`) |

| Z16 | «аксолотлик» с записанными логитами модели слов | «аксол+отлик», как у Python | `RuAccentReplayTests` |

**Пробы причуд** — свои тесты:
- нечётная гипотеза переключает путь;
- особое слово режется тройками, чётная группа больше трёх — парами;
- `fix_capital` при разной длине;
- перенос нескольких «+»;
- знак модели слов на позиции 0 — на последней букве, как в Python.

## Non-functional

- Linux, только Foundation.
- Файл ≤ 500 строк, функция ≤ 50, сложность ≤ 8.
- Фикстура < 512 КБ: данные RUAccent (MIT) и фразы стенда; детских данных нет.
- План ≈ 490 строк, с поправкой ≈ 735 из 800; выше 780 — стоп и доклад.

## Стыки (ведущий, 2026-10-23)

- **Пакет** `Packages/AllyAccent` (V3a, ветка `feat/voice-accent`, a73c80b) — логика V3b в том же таргете;
  зависимость на `../AllySpeechText` добавляет V3b.
- **Протокол `AccentModels`** — выше; входы моделей ровно те строки, что Python подаёт токенизатору:
  - «ё» — `lower_sentence`;
  - омографы — текст после `re.sub(r'\s+(?=(?:[,.?!:;…]))', '', text)` и гипотеза;
  - модель слов — `lower_word`.
- **Запись Python** на 163 позициях — исполнитель V3a, JSONL в `~/models/tts/ruaccent-parity`.
  - Строка на вызов: `{pos, model, text, pair?, ids, logits}`.
  - Строка на позицию: `{pos, text_in, text_out}`.
  - V3b просит добавить разметку токенизатора — `tokens`, `offsets`, `special` — и позицию «аксолотлик» (Z16): без
    них повтор в CI потребовал бы файлов токенизаторов.
- **Словари — простые JSON:** `.gz` распаковывает команда копирования V4.
