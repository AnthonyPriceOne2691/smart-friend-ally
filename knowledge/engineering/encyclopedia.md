# Purpose

E4B «по памяти» ошибается в 15% детских «почему» ([справка](/references/research/kids-encyclopedia.md)); с верной
карточкой в подсказке — 43 из 48 (цель родителя 5). Факты берутся из проверенной базы карточек, а модель пересказывает
их своими словами. С поставки Э2 приложение грузит базу на прогреве, а сессия спрашивает энциклопедию на каждой реплике,
которую маршрутизатор пропустил к модели.

# Canonical rules

- **Подсказка — только когда поиск уверен** (решение родителя 2026-10-23). Неверная подсказка хуже, чем никакой: модель
  уверенно перескажет чужой факт. Промах оставляет ход как сейчас.
- **Порядок решения:** нет вопросительного слова → `knowledge.not_asked`; «ты/твой/мой…» → `knowledge.personal`;
  деликатное начало слова (смерть, гибель, война, похороны) → `knowledge.delicate`; ни одна карточка не делит основу →
  `knowledge.no_match`; лучшая карточка не покрывает значимые слова вопроса → `knowledge.coverage`; иначе
  `knowledge.hint` и ответ карточки слово в слово.
- **Строгое покрытие:** все значимые слова вопроса (без стоп-слов и глаголов-рамок) есть в формулировках карточки — по
  основе или по основе детского синонима. Из трёх и больше одно может не найтись, но только поверх целой формулировки
  карточки в её вопросе: «почему лёд тает быстро» держит «почему лёд тает», а «почему мышка спит всю зиму» не держит ни
  одной формулировки медведя (Э2, после провала P16 на v3 — без карточки чужая подсказка в 3 из 40). Ответ карточки в
  покрытие не входит.
  Замер 2026-10-23 (55 карточек стенда, 300 открытых вопросов): правило справки (покрытие ≥ 0,5 по всей карточке) —
  неверная подсказка на 58 из 178 вопросов без карточки; строгое — на 4, верных с карточкой 72 из 90 вместо 84.
  Замер 2026-10-27 (финальная база из 100 карточек, те же 300 вопросов): все 8 неверных подсказок шли через пропуск
  одного слова, и пропущенное было сутью вопроса («мышка», «кит», «синяя», «дышат»); требование целой формулировки
  снимает 7 из 8 ценой 6 из 90 верных (формы слова и синонимы, которых нет в формулировках: «усищи», «спят»).
- **Основы слов — Snowball для русского** (свой перенос, BSD-3): одинаково в CI на Linux и на телефоне. На всём словаре
  Snowball (49 785 слов) совпадает с эталоном. Леммы Apple NLTagger не берутся: их нет на Linux, они меняются с iOS, а
  строгое правило на них не лучше (70 верных против 72).
- **Поиск — SQLite FTS5** через общий пакет приложения `Packages/AllySQLite` (решение ведущего: SQLite у приложения один).
  Таблица без содержимого строится в памяти при загрузке — файла базы нет ни в git, ни на диске. Поля и веса: первая
  формулировка 4, остальные 2, ответ 1; запрос — «или» по основам с синонимами, `bm25`; буст первой формулировки — в
  Swift. FTS5 проверен пробой на macOS 27 (SQLite 3.54.0) и в Ubuntu 24.04 (3.45.1, как в CI); на iPhone — самопроверка Э2.
- **Отказ закрытый:** негодная карточка или конфиг, или первая формулировка, не нашедшая свою карточку, — подсказок нет
  совсем (`knowledge.selftest_failed`); таблица FTS5 не создалась — `knowledge.index_failed`. Так устроены маршрутизатор
  и контракт: дефект виден, база не урезается тихо.
- **Запись решения без слов:** id карточки (латиница), правило, хэш данных `fnv1a:` конфига и карточек.
- **Где спрашивают (Э2):** только на «pass» маршрутизатора, кроме её прощания и реплики с `forget`. На скрипте, `guard`
  и фразах сессии поиска нет, и поля `knowledge` в следе хода нет — отсутствие видно (P17).
- **Подсказка во входе модели (формат B):** её фраза, затем строкой «Подсказка к вопросу девочки — верный ответ:
  <ответ>» в той же реплике пользователя; рамка — `hint_frame`, место — `hint_place: after` в `encyclopedia.json`. Ход с
  подсказкой — в режиме `why`; последний ход после лимита остаётся `goodbye`. Без подсказки модель получает её фразу
  байт в байт, как до Э2. Спекуляция начинает ответ с тем же входом.
- **Почему B (P18, 2026-10-27):** на `er` × seed 42–44 формат A дал 24 из 48 — модель принимала строку перед её фразой
  за слова девочки («какая ты умница», «а ты как думаешь?»), почти как без подсказки (23); B — 36, отдельная системная
  реплика — 34. Ключ судьи `er01` писался под карточку справки и не узнавал ответ новой; по решению родителя судья
  засчитывает суть по ключу вопроса или по ключу найденной карточки, B перегнан на свежих seed. Формат A из продукта
  убран: `hint_place: before` отвергается самопроверкой.
- **Текст карточки, когда в ответе нет сути** (card-fallback, решение родителя 2026-10-29 «Подписываю: фраза +
  карточка»). На ходе с подсказкой ответ модели проходит контракт, как прежде. Если ключ карточки (`key`) не находит
  суть в том, что контракт оставил для голоса, вместо остального звучит текст карточки. Уже прозвучавшая первая фраза
  остаётся: «Ой, какой ты умненький! Вода всё время выталкивает вверх…».
  - Суть ищется строчными, «ё» как «е», без учёта регистра — как в тесте базы P13 и у судьи P18. Сырой ответ не
    судится: контракт может срезать фразу с сутью, а ключ `солн` в сыром тексте ловит обращение «солнышко».
  - Карточка проходит контракт того же хода после первой фразы, как строка скрипта. Все 100 карточек проходят `why`,
    `talk` и `goodbye` слово в слово, а в `why` — и после первой фразы в 22 слова (P24).
  - Заготовку контракта (отказ, тайм-аут, «ничего не осталось») карточка не заменяет. Ответ из одного предложения —
    звучит одна карточка. Последний ход после лимита — то же правило, после него прощание.
  - След: `knowledge.rules` — `knowledge.hint`, `knowledge.fallback`; источник — `model`; память модели —
    прозвучавшее. Консоль новой строки не пишет: текст карточки виден в `said`.
  - Задержки откат не добавляет: остаток хода и прежде звучал после конца ответа модели.
  - Ключ читает и движок: ключ, который не собирается или не ловит собственный ответ, выключает энциклопедию
    (`knowledge.selftest_failed`). Карточка без ключа (тестовая база Э1) текстом не звучит.
  - Цена — живость: по пересчёту прогона seed 45–47 карточка звучит примерно на каждом третьем «почему» с карточкой
    (16 из 48). На части этих ходов пересказ был верным, но строгий ключ его не узнал («чувствовать» при `чувству`).
- **База — ресурс AllyCore** `encyclopedia.ru.jsonl`: тест всей базы идёт в CI (P12, P13). Приложение на прогреве пишет в
  консоль число карточек и p95 поиска по всем формулировкам, или «энциклопедия: выключена» с причиной.
- **Карточка** — строка JSONL: `id`, 3–6 формулировок с вопросительным словом, ответ 1–2 предложения ≤ 130 знаков
  (рамка подсказки 13 токенов + ответ ≤ 46 — вместе ≤ 60 токенов Gemma), `topic`, `key` и `avoid` для судьи пересказа
  (`key` с card-fallback решает и откат на текст карточки),
  `sources`, `license: own`. В базе нет тем маршрутизатора, деликатных тем и советов «что делать в опасности».

# Серия

- **Э1 `encyclopedia-core`** — движок, тесты P1–P10 на Linux, паритет P11 с эталоном на Python (`encyclopedia-replay`).
- **Э2 `app-encyclopedia`** — 100 карточек (по 10 на группу) с двумя проверками фактов и слепыми судьями, слепой набор
  v3, крючок сессии: на «pass» маршрутизатора — поиск, ход с подсказкой в режиме `why`, телефон. Брифы и стенд —
  `local/spike/erudition/cards-v1/` (вне git). Замеры: v3 — без карточки чужих 3 из 40, после правки правила v4 — чужих
  0, с карточкой 26 из 40 (решение родителя «Принять строгий»); P18 — формат B, 38 из 48 на свежих seed, все промахи —
  переспросы (решение родителя «Слить, чинить сразу после»).
- **`card-fallback`** — текст карточки, когда в ответе нет сути (примеры P21–P24, подпись родителя 2026-10-29), перегон
  P18 на свежих seed 48–50 тем же замороженным судьёй, стенд с шагом продукта (`encyclopedia-replay --said`).
- **Отложено:**
  - добор попаданий P16 — формулировками карточек из настоящих вопросов дочки (чёрный ящик), а не ослаблением правила
    (решение родителя 2026-10-27);
  - ключи карточек, которые не узнают верный пересказ, — по данным чёрного ящика (доля `knowledge.fallback`), а не
    правкой правила отката.
