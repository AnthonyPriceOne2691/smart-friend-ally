# Рантайм модели

- **Учёт памяти iOS.** jetsam ограничивает `phys_footprint`: анонимная, сжатая, iokit-память и
  таблицы страниц; «чистые» страницы файла, отображённого только на чтение, в него не входят —
  по исходникам XNU и словам инженера Google [агент]. Наш замер: E4B в llama.cpp — footprint
  0,4–0,5 ГБ при resident 3,1–5,8 ГБ [замер].
- **llama.cpp** отображает GGUF в Metal-буферы без копирования (`newBufferWithBytesNoCopy`) [агент];
  у Gemma 4 тензор `per_layer_token_embd` помечен для ленивого чтения, режим `auto` включает его
  только для тензоров больше 4 ГиБ, поэтому для E2B/E4B нужен явный `on` [агент; лог зонда
  подтверждает «lazy read enabled» для 1848 МиБ при `on`, замер]. В b11599 (2026-10-13) — правка
  Metal-буферов для этой таблицы [агент]; у нас b10809, паритет с бейк-оффом.
- **LiteRT-LM v0.18.0** (2026-10-06): iOS через SPM, бинарный `CLiteRTLM.xcframework` [сверено:
  релиз]; Swift API — «Early Preview», GPU-делегат Metal закрыт и собран заранее; бэкенды на iOS —
  CPU и GPU [агент]. Модели `litert-community/gemma-4-E2B-it-litert-lm` и `…-E4B-…` — Apache-2.0,
  без гейта [сверено: HF API]. Открытый баг: на GPU с fp16 портятся цифры в ответах Gemma 4,
  обход — `float32` активации [агент].
- **Числа Google для iPhone 17 Pro** (prefill 1024, decode 256, контекст 2048): E4B на GPU —
  25,1 ток/с, первый токен 0,9 с, память 3380 МБ; E2B на GPU — 56,5 ток/с, 1450 МБ [агент: карточки
  моделей]. Наш llama.cpp: E4B 13 ток/с, E2B 32 ток/с [замер].
- **MLX** копирует веса в свою память, и они идут в footprint целиком: E2B 4-bit ~3 ГБ [агент] —
  для нас хуже llama.cpp.

# Распознавание

- **SpeechTranscriber без русского:** на macOS 27 — 45 локалей без `ru` [агент: проба на Mac]; на
  iOS 27.0.1 — тоже нет [замер]. **DictationTranscriber** — `ru-RU` есть, модель уже стоит в системе,
  формат 16 кГц Int16 моно [замер].
- **Конец реплики:** встроенная финализация по тишине медленная — 1,1–1,9 с для русской диктовки
  [агент: Mac]; свой определитель конца речи и `finalize` дают окончательный текст через 0,03 с
  [замер]. `SpeechDetector` — только экономия энергии, не определитель конца речи [агент: SDK].
- **Опции диктовки:** `.frequentFinalization` (без неё у диктовки нет `isFinal`) [агент], пунктуация
  `.punctuation`, подсказки `.shortForm`, `.atypicalSpeech`, `.farField`; `contextualStrings` —
  до 100 фраз, например имён [сверено: SDK iOS 27]. Кандидаты для детской речи — шаг 3.
- Распознавание идёт вне памяти приложения: модель «operates outside of your application's memory
  space» (WWDC25) [агент]; в нашем замере footprint зонда с распознаванием не вырос [замер].

# Синтез

- На телефоне из коробки русский голос один — Milena compact, качество 1 [замер]; улучшенные
  Milena, Katya, Yuri качаются в Настройках [агент].
- Первый буфер синтеза — 0,02 с после прогрева [замер]; без прогрева ~0,3 с [агент: Mac].
  `didStart` срабатывает на начале озвучки, а не на звуке из динамика [агент].
- **Supertonic 3:** репозиторий в архиве с ~2026-09-09; пример для iOS — XcodeGen, ONNX Runtime
  через SPM, только CPU, без потоковой выдачи; модели — `supertone-oss-archive/supertonic-3`,
  OpenRAIL-M, ~99M параметров, 44,1 кГц; русский — сырой текст без G2P, знак ударения U+0301 даёт
  артефакты по словам сопровождающего; есть Core ML конверсия [агент]. Вход в шаг 4 (голос с дочерью).
