# Purpose

Утечка данных ребёнка необратима. Запись голоса, попавшая в историю git, убирается
только переписыванием истории, а с GitHub — ещё и обращением в поддержку. Поэтому
правило держит механика, а не дисциплина.

# Canonical rules

- **Что считается данными ребёнка:** записи её голоса (в том числе для теста
  распознавания на спайке), транскрипты разговоров, база памяти, журналы с её
  репликами, выгрузки с телефона.
- **Чёрный ящик:** обе стороны каждой детской сессии (`audience:
  supervised`; детский экран открыт всегда с 2026-10-29) — текст и звук — пишутся на телефоне и выгружаются только на Mac
  родителя, без облака (решения пользователя 2026-10-02 и 2026-10-22) —
  [Black box](/ops/black-box.md).
- **На Mac — только в `local/`.** Каталог игнорируется git; там живут выгрузки
  чёрного ящика (`local/blackbox/`) и записи для сравнения распознавателей. Скрипт
  выгрузки отказывается писать в каталог, синхронизируемый с iCloud.
- **В git — никогда.** `.gitignore` закрывает `local/`, аудио, файлы баз и записи
  чёрного ящика (`*.allybox`) по расширению. Игнор обходится `git add -f` молча,
  поэтому гейт `scripts/lint/check_child_data.py` на каждом коммите и в CI проверяет
  индекс и неигнорируемое дерево по трём правилам: каталог `local/`, расширение и
  **сигнатура содержимого** (переименованная запись `voice.bin` расширение-правило
  проходит, сигнатурное — нет). Допуск ноль, снимка и мягкого режима нет.
- **Спутники базы — тоже данные:** в режиме WAL свежие записи памяти о ребёнке лежат в `-wal` до чекпойнта, журнал
  отката держит прежние страницы. `.gitignore` закрывает `*.sqlite-*` и `*.db-*`, гейт знает `-wal`, `-shm`,
  `-journal` по расширению, WAL и журнал — по сигнатуре (поставка memory-core, смоук S7; проба 2026-10-23: до неё WAL с
  записью под тремя именами проходил гейт с выходом 0).
- **Текст разговора гейт узнаёт только по заголовку записи чёрного ящика** —
  первой строке `ALLY-BLACKBOX/1` каждого текстового файла ящика (поставка
  black-box, 2026-10-22): переименованная запись `case.json` до неё проходила гейт
  зелёной. Заголовок обязан стоять первым и в производных файлах на Mac. Фразу,
  перепечатанную руками, гейт не видит — по кириллице он краснел бы на знании и
  фикстурах; держит это правило: в git — только пересказы, которые родитель написал
  сам. Проба исполнением — смоук S6 (`delivery/evals/smoke/child_data_blackbox.sh`).
- **Неигнорируемый аудиофайл в дереве — тоже нарушение**, даже не добавленный:
  до коммита его отделяет один `git add -A`.
- **На телефоне:** база памяти и транскрипты помечаются
  `isExcludedFromBackup = true` — иначе они уехали бы в iCloud вместе с бэкапом
  телефона (KNOWLEDGE.md §9). С `memory-app` (2026-10-27): `Library/Application Support/Memory` — база памяти и её
  очередь (её реплики с ответами Элли до разбора, затем стираются с чекпойнтом WAL); пометка читается обратно, база с
  флагом полной защиты; не прочиталась — память не пишется (`MemoryFiles`). С `memory-recall`: когда блок памяти
  включён (новая форма, решение родителя 2026-10-29), файл префикса `Library/Caches/persona-*` несёт его — класс
  полной защиты, Caches в бэкап не идёт, «Стереть память» пересобирает префикс из персоны и удаляет файл с блоком.
  С `memory-forget` (2026-10-29): «Забыть» один факт или сущность удаляет строки с историей и повторами,
  `secure_delete` их затирает, чекпойнт `TRUNCATE` опустошает WAL — ни байта значения в базе, WAL и SHM (M41);
  надгробие хранит кто, что и когда, но не значение — ни открытым, ни хэшем; разговор из очереди с этим словом
  стирается после своего разбора, как любой.
- **Продукт не ходит в сеть** — данным некуда уйти с телефона, кроме выгрузки родителем.
- **Запись о нарушении контракта** — id правил в следе хода; текст модели до контракта и сказанное после —
  в записи чёрного ящика.
